## Наблюдения и требования для будущего задания

### NX-052-01 — управление Claude (P1)
- **Факт 2026-11-02:** `list_windows` на Windows показал `process:"claude"`, PID `9016`. `window_info({pid:9016})` → `app_not_allowed: owner_handoff_required hard_deny` (trace `92d433231731bf86`). Прямая попытка `mouse_action({action:"scroll",x:1025,y:290,amount:3})` при открытом окне Claude → `target_not_allowed: owner_handoff_required hard_deny` (trace `08d46f0959134c0a`). Прокрутки не произошло; остановлено без обхода.
- **Проверка кода:** `nexus-host/policy.mjs` текущей экспериментальной ветки содержит `'claude'` в `DENY_APPS`, классификатор возвращает `{cls:"deny",level:"handoff",reason:"hard_deny"}`. Из-за общей метки процесса может смешиваться GUI Claude и CLI/агент Claude Code — **это гипотеза о замысле**, не подтверждённая причина дефекта.
- **Потребность владельца:** по явно направленной команде безопасно читать и прокручивать **GUI Claude** при сохранении запрета на shell/CLI, чужие процессы и секреты.
- **Предлагаемое направление:** раздельная идентификация доверенного GUI Claude (подписанный package identity / конкретный image path / процессная принадлежность, реальная Windows-проверка) и CLI Claude Code. НЕ снимать запрет со всех процессов с именем `claude` по умолчанию; отдельная матрица read/focus/scroll/input, fail-closed при неопределённой идентичности.
- **Критерий будущего PASS:** в установленном GUI Claude `window_info`, разрешённый `inspect_ui` и безопасная `scroll` работают по политике владельца; для CLI, терминалов, логинов и защищённых контекстов сохраняется отказ. Тесты выполнять только с фиктивным текстом.

### NX-052-02 — видимость Claude через screenshot при hard deny (P1 security review)
- **Факт:** `capture_screen` возвращал изображение, где текст сообщения Claude можно было визуально прочитать и пересказать; `watch_nexus` давал `streaming:true`. Одновременно `window_info` и `mouse_action scroll` для `claude` отклонены `hard_deny`.
- **Не утверждать автоматически:** это не доказательство утечки без разрешения владельца — в текущем сеансе сам владелец явно просил прочитать текст и включить демонстрацию. Однако **политика прямого API-доступа и политика видеозахвата различаются**.
- **Задача:** явно определить, должны ли окна `deny/protected` маскироваться в `capture_screen` и Live View; если да — расширить fail-closed маски с Notepad на защищённые приложения. Если нет — документировать осознанное разграничение, проверять разрешение на экран.
- **PASS:** тест на фиктивном защищённом окне подтверждает одинаково обоснованное поведение UIA/скриншота/Live View и не раскрывает секреты неожиданно.

### NX-052-03 — ChatGPT launcher (P2)
- **Факт:** после закрытия окна `ChatGPT`, PID `15152`, `manage_app_access({action:"list"})` не находил `chatgpt` среди 31 installed, `open_app({app:"chatgpt"})` → `app_not_found` (trace `3db2cf5b2368610a`).
- **Контроль успешного обхода функциональности без изменения политики:** `inspect_ui` у Explorer показал закреплённую на панели задач кнопку `OpenAI.Codex_2p2nqsd0c76g0!App`, имя «Приложение ChatGPT закреплено». `mouse_action click` по этой кнопке → `foregroundAfter:"ChatGPT"`; затем `list_windows` и `window_info` подтвердили окно ChatGPT PID 15152. Позже `close_window` с `ownerRequested:true` → `closed:true`.
- **Задача:** расширить обнаружение и запуск MSIX/UWP/packaged Desktop, не полагаясь исключительно на .lnk/.exe; без выдачи shell доступа и без вмешательства в параметры безопасности.
- **PASS:** `open_app chatgpt` через штатный инструмент запускает/активирует именно GUI ChatGPT, возвращает `createdByNexus` с корректной принадлежностью и соблюдает lifecycle. Уже подтверждённый запуск через кнопку панели задач повторять без причины не нужно.

### NX-052-04 — pause/resume/checkpoint (P2)
- **Факт:** 20:16:53 UTC `owner_pause why:"mouse"`, затем `lease_expired` в 20:18:02 UTC. `ownerPaused` сохранялся, самовозобновления не произошло. После явной команды владельца `live_control({action:"resume"})` вернул `resumed:true`, `ownerPauseCleared:true`.
- **Ограничение:** предыдущая задача `t-554f93f86836` осталась `interrupted` на `focus_window`; следующие действия шли в новой задаче `t-01e1f69d3c7a` и новой сессии. Было продолжение по смыслу без повторного запуска Explorer; **требование того же task ID не доказано**.
- **Задача на решение:** специфицировать N-08: ожидается восстановление исходного ID или безопасная новая дочерняя задача с указанием связи `resumedFrom`, завершённых шагов и защиты от дублей? Не менять поведение без решения о гарантиях идемпотентности.
- **PASS:** тест пауза >1 мин → явный Resume → сохранён шаг, связь с исходным checkpoint, нет повторных внешних операций, audit позволяет восстановить всю историю.

### NX-052-09 — мобильный Live View lifecycle (P2 UX)
- **Факт:** `watch_nexus` фактически включал `streaming:true` и отображение на телефоне; `live_control status` показывал `viewing:true`, счётчики кадров. `finish_task` завершал трансляцию с `liveActive:false`. Отдельная watch-сессия имеет idle lease около 45 секунд, после которого эфир завершается. Пользователь специально просил **сначала экран, затем операция**, и такая последовательность прошла (watch → close ChatGPT → проверки → finish_task).
- **Функциональный запрос:** наблюдение на телефоне с рабочим STOP без необходимости искусственно повторять команды только для поддержания эфира; отдельный проверенный жизненный цикл эфира/операций, автоматическое завершение по STOP и понятное отображение статуса.
- **PASS:** Live View виден до первого действия, непрерывно передаёт кадры при работе, STOP останавливает задачу, по завершении нет утечек кадров. Согласовать ресурсные лимиты и тайм-ауты, не делать бессрочную трансляцию по умолчанию.

### NX-052-12 — регламент handoff (P2 process)

### NX-052-13 — ложная классификация клика в Edge (P2, 02.11)
- **Предусловия:** пользователь попросил открыть сайт поиска квартир в Италии с Live View сначала на телефоне. `watch_nexus` → `streaming:true`; `browser_open({url:"https://www.affitto.it/"})` → URL, корректный title и `profile:"nexus-separate"`. `browser_snapshot` подтвердил форму `Abitativi → Affitto`. Снимок `capture_screen` показал поверх сайта системную подсказку Edge «Перевести страницу с итальянского?» (экран 1280×720, снимок 1024×576, imageToScreen=1.25).
- **Фактический сбой:** попытка убрать всплывающую подсказку одним `mouse_action({action:"click",x:783,y:110})` вернула `consent_required`, `kind:"window"`, цель `msedge: окно «Case e appartamenti in affitto da privati e agenzie - Affitto.it — Личный: Microsoft Edge»`, с заявлением, что закрывается чужое окно NEXUS. Это был **запрос согласия**, фактического клика/закрытия не было. Действие немедленно отменено `confirm_action decision:"cancel"` → `cancelled:true`.
- **Неизвестно:** почему нажатие на предполагаемый крестик подсказки было классифицировано как закрытие окна, и почему окно показано как не принадлежащее NEXUS, хотя `browser_open` сообщает `nexus-separate`. Нет данных о фактическом контроле под координатами, поэтому не считать доказанным дефектом политики или утечкой.
- **Проверяемая доработка:** отдельно сопоставлять ownership браузера из CDP и GUI, инспектировать точный UIA-элемент под координатой перед `close_window`/кликом; выдавать точное `consent_required` только для настоящей кнопки закрытия чужого окна. Не ослаблять защиту закрытия пользовательских окон.
- **Будущий PASS:** на тестовом Edge всплывающую подсказку перевода можно безопасно закрыть без запроса на закрытие всего окна, либо строго вернуть `target_not_allowed` с корректным объяснением; пользовательские окна остаются нетронутыми.
- **Очистка:** `finish_task` → `ended:true`, `browser.wasOpen:true`, `steps:["cdp_browser_close"]`, `remaining:0`, `liveActive:false`. Следовательно, сайт был открыт и показан в ходе теста, но **не оставлен открытым** после штатной очистки NEXUS.
