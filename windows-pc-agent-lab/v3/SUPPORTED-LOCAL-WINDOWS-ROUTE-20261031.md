# Windows 11 — разрешённый маршрут к практическому управлению (31.10.2026)

## Решение
**Операционную цель ChatGPT → локальный Windows 11 рекомендуется реализовать прежде всего через штатные ChatGPT Work Local + Computer Use + Remote connections, если функция доступна и разрешена в текущем аккаунте.** Не считать это завершённым подключением до фактического теста. Это продуктовый маршрут, а не новая публикация или обход ограничений для Windows Agent v3.

Официальные источники (проверены 31.10.2026):
- [ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex) — Work Local в desktop-приложении, работа с файлами и приложениями с разрешения пользователя.
- [Computer Use](https://learn.chatgpt.com/docs/computer-use) — компьютерное управление Windows/macOS, разрешения приложений, Windows foreground; **нельзя** обходить системные подтверждения, вводить права администратора или автоматизировать терминал через Computer Use.
- [Remote connections](https://learn.chatgpt.com/docs/remote-connections) — подключённый Windows-host, удалённое продолжение со второго устройства; состояние зависит от поддержки продукта, прав workspace, подключённости хоста и доступности сеанса.
- [Antigravity Remote Control](https://antigravity.google/docs/remote-control?tab=cli) — возможная отдельная альтернатива для управления **агентом, запущенным на самом Windows**, но ранее проверенный Antigravity в Linux Codespaces не имеет прямого доступа к локальному Windows.

## Почему не продолжать попытки публикации заблокированного v3
- В опубликованном `windows-pc-agent-lab/v3/` подтверждены лишь `actions.mjs`, `identity-v3.mjs`, часть тестов и документация.
- `worker-v3.mjs`, `windows-agent-v3.mjs`, `schema-v3.sql` и полный CI отсутствуют; предыдущее ограничение публикации исполняемых компонентов действует.
- Нельзя использовать TinyFish, GitHub Actions, Cloudflare, артефакты, кодирование или другой коннектор как обход отклонённой публикации.
- Поэтому **не выдавать v3 за работающий Windows-канал**, не развёртывать worker/schema и не открывать новые grants.

## Минимальная проверка штатного пути — строго по шагам
1. **Проверить наличие**, а не автоматически переустанавливать, официального ChatGPT desktop app на локальном Windows 11. Если установлен, открыть ту же учётную запись и проверить Work/Computer Use (Plugins → Computer Use); местные/роль-права и доступность функции могут отличаться.
2. Пользователь разрешает штатные права только на тестовую программу (например, Windows Calculator). Не давать общий постоянный доступ ко всем приложениям, не открывать Bitwarden, аккаунты, production, ключи, личные файлы.
3. Создать новую задачу Work **в desktop-приложении**, потому что существующая облачная беседа сама по себе не приобретает локальный доступ. Проверить приёмку: открыть Calculator/Notepad через Computer Use, показать проверяемый результат. Никакой shell и скрытой установки служб.
4. При подтверждённой возможности Remote connections — проверить продолжение той же задачи с Samsung, когда Windows online и разблокирован. Это отдельная приёмка, не логическое следствие местного теста.
5. После PASS решить, какие функции действительно требуют собственной v3 разработки (например, строго машинные задачи, отсутствующие в Computer Use), и только затем возвращаться к проектированию отдельного контролируемого сервиса на разрешённом пути.

## Критерии приёмки
- `WIN_LOCAL_ACCESS`: реальная работа в локальном Windows 11 с пользовательским разрешением, чтение/управление **только** тестовым приложением.
- `PHONE_REMOTE_CONTINUATION`: та же задача доступна через поддерживаемую мобильную Remote connection, PC включён и сеанс разблокирован.
- `NO_IMPACT`: production/main, Cloudflare, действующий v2, Windows автозапуск/службы и ключи не изменены.
- `NO_NEW_PAID_RESOURCE`: никаких новых платных продуктов, подписок, Codespaces, пополнений.
- `LIMITATION`: Computer Use в Windows работает на переднем плане, не в фоне при параллельной работе пользователя; не является безусловно автономным сервисом 24/7.
- Если Work Local не показывается или недоступен: **STOP**, зафиксировать точный статус аккаунта/устройства; не угадывать и не подменять инструмент.

## Проверено в текущей ChatGPT сессии
- Прямого коннектора к локальному Windows хосту в доступных инструментах **нет**. Проверка права на Work Local/Computer Use и состояния установленного Windows desktop-приложения через текущие GitHub/Cloudflare/TinyFish коннекторы невозможна: их облачные сеансы **не равны** локальному рабочему столу пользователя.
- Этот документ — зафиксированное техническое решение и регламент приёмки, **не свидетельство**, что локальное подключение уже включено.
- Запрещённые исполняемые компоненты v3 не публиковались, production не изменён.
