# Chat-first Windows control — самостоятельный канал без Work
**Дата:** 2026-10-31 · **Статус:** DESIGN READY / LOCAL EXECUTOR NOT ACTIVE / RELEASE BLOCKED

## Решение после уточнения пользователя
Работа из **обычного ChatGPT-чата**, без Work / Astra Work и его отдельного лимита. Повторно не использовать Work Local в качестве основного исполнителя; не предлагать ещё одну платную подписку. Существующая связка ChatGPT ↔ Cloudflare Entoni MCP ↔ Cloudflare Workers/D1 ↔ Windows должна служить основой. Главная цель — разрешённая работа с графическим интерфейсом **собственного Windows 11 пользователя**, при явном выборе приложения и возможностью остановить выполнение.

## Что проверено фактически
- Прямые инструменты Cloudflare Entoni MCP доступны в обычном чате: read-only запросы к уже существующей D1 работают, отдельный Work-режим не нужен.
- D1 `pc-agent-readonly-lab` содержит **одно approved v2-устройство**, `last_seq=5`, `last_seen_at=1793468912` (2026-10-31 17:48:32 UTC). Это **последний сохранённый heartbeat**, не доказательство текущей активности Windows-процесса.
- Уже работающий v2 — foreground signed telemetry с ECDSA P-256 и DPAPI CurrentUser; **никакого polling задач и GUI-интерфейса в v2 нет**. Новое enrollment не требуется при повторном использовании того же устройства, но локальная доступность должна быть отдельно подтверждена.
- v3 в GitHub содержит разрешённые `actions.mjs`, `identity-v3.mjs` и CI PASS; однако полный polling-клиент, Worker v3 и схема D1 **не опубликованы** после прежнего отказа средства публикации. Релизный gate обязателен, не обходить другими именами/инструментами/архивами.
- Уже существующий Chat Router Android MCP **не является** Windows desktop connector. Antigravity в Linux Codespace управляет Linux Codespace, а не Windows.

## Публично подтверждённая технологическая основа (не копия закрытой Work)
1. OpenAI Remote connections: клиентская среда и подключённый host, защищённый relay, допуски к приложениям; Windows Computer Use управляет **foreground** в разблокированном сеансе.
2. Microsoft Windows UI Automation: семантическая структура окон/контролов и их доступные действия; надёжнее слепой мыши для поддерживаемых приложений.
3. Windows.Graphics.Capture: захват **выбранного пользователем** окна/экрана через системный picker и доступ; никакого скрытого capture.
4. Cloudflare Workers/D1 используются как структурированный control plane, а не как публичный произвольный shell. Динамические команды ОС, скрытые процессы, отключение безопасности и самовольное повышение прав исключены.

## Архитектура в рамках существующей инфраструктуры
```
Обычный чат GPT-6
   | разрешённый инструмент Cloudflare Entoni MCP (уже подключён)
   v
Cloudflare Worker / D1: авторизация, конкретная задача, TTL, состояние, аудит
   ^  |  только исходящие запросы с Windows (никаких входящих портов)
   |  v
Windows-local исполнитель в активном пользовательском сеансе
   |-- идентичность уже согласованного v2 (DPAPI + подпись)
   |-- allowlist конкретных приложений и UI Automation операций
   |-- OS-controlled window capture по согласию и только для разрешённого окна
   |-- локальная кнопка STOP, короткие сроки разрешения, проверяемый результат
   v
Локальный интерфейс Windows → ограниченный ответ → D1 → этот чат
```
**Важное уточнение:** наличие Cloudflare MCP позволяет чату обращаться к облачному control plane, но **не означает**, что отсутствующий локальный исполнитель можно запустить удалённо. Первичная установка/разрешение на Windows неизбежно требует авторизованного локального действия, если нет ранее действующего Windows-канала.

## Операционный контракт — первый этап
- **Scope:** одно тестовое приложение (Calculator или Notepad), один Windows foreground-сеанс, одна задача; **не** работа с личными папками, токенами, браузерными аккаунтами или системными настройками.
- **Получение:** Windows самостоятельно делает HTTPS запрос с криптографически подтверждённой v2 device identity; ответ строго содержит id операции из allowlist, срок, application identity и обязательные UI-permission flags.
- **Проверка:** device grant + application allowlist + deadline + nonce/sequence replay protection + предотвращение повторного выполнения + аудит постановки/исполнения/отказа. При конфликте, stale timestamp или невозможности установить фокус — STOP.
- **Действия:** сначала `observe_allowed_window` и `inspect_accessible_controls`; только затем отдельное явно разрешённое `invoke_control` с проверенным control identifier. Не реализовывать «выполни любую команду» и «нажми в случайных координатах».
- **Фотографии/скриншоты:** только OS-approved window selection; передача результатов отдельно разрешается пользователем; удалять по TTL, приватные данные не отправлять по умолчанию.
- **Наблюдаемость:** ACK/NACK, код результата, latency, audit log без ключей/секретов, явное локальное отображение активного сеанса.
- **Выключение:** локальный STOP имеет приоритет, отозванный grant не может возобновлять новые операции, при закрытом/заблокированном Windows-сеансе — fail closed.
- **Никакой самопроизвольной круглосуточной службы, Task Scheduler, Windows admin, credential harvesting и обхода UAC.**

## Недостающий конкретный компонент
Не хватает **локального пользовательского Windows UI-исполнителя**, который принимает строго ограниченные задачи и работает через Windows UI Automation в разрешённом приложении. Рабочий v2 по архитектуре только отправляет signed heartbeat; расширение данного клиента должно пройти отдельную проверку прав доступа, безопасности и локальное согласие.

Публикация полного исполняемого v3 через текущий инструмент ранее была отклонена. Этот документ **не является** попыткой обойти отказ. Не публиковать исполняемый сервер/клиент/SQL через другие коннекторы, имена, фрагменты или артефакты. Следующая стадия требует допустимого, прямо разрешённого пути публикации и исполнения, затем полного CI; до этого считать релиз BLOCKED.

## Приёмка, строго отдельно
1. `CLOUD_READ` — из обычного чата прочитан v2 device heartbeat в D1 (**PASS**, не управление).
2. `DEVICE_ONLINE` — локальный Windows-процесс реально отвечает на свежую задачу (**NOT VERIFIED**, v2 это не поддерживает).
3. `UI_READ` — с явным согласием пользовательской сессии подтверждён read-only доступ к конкретному окну (**NOT IMPLEMENTED**).
4. `UI_ACTION` — после отдельного разрешения выполнено действие в выбранном приложении, readback и audit (**NOT IMPLEMENTED**).
5. `NO_WORK` — ни один этап не требует Work / Astra Work (**планируемая архитектура**, измерить по фактическому пути).
6. `NO_RISK` — production/main/working v2/реальные Windows-пользовательские данные не изменены (**PASS для данного исследования и документа**).

## Следующее инженерное решение
Первое препятствие — **не модель GPT и не Cloudflare**, а локальный компонент и разрешённый процесс его поставки. Заранее не тратить TinyFish и Work, не перевыпускать существующие ключи и не открывать grants. До появления разрешённой, локально подтверждённой Windows-интеграции дальнейшие облачные задачи не дадут доступа к GUI.

Это описание интерфейса и механизма, не подтверждение рабочего удалённого контроля.
