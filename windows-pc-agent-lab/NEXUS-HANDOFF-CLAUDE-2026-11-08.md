**Статус:** НЕ ПРИНЯТО (FAIL по реальному UX на Samsung). Этот файл — новый сводный чекпоинт. Он заменяет устаревшую оценку готовности интерфейса, но не переписывает историю старых отчётов.

## 1. Что хотим получить (критерий конечного результата)
NEXUS — управляемый владельцем удалённый агент для его Windows 11 через ChatGPT, Claude и подключённые инструменты. Результат оценивается **реальной работой на телефоне**, а не наличием коммитов и зелёных тестов.

Ближайший MVP/приёмка:
1. Встроенный **NEXUS Live прямо в чате ChatGPT на Samsung** показывает Windows и позволяет управлять ею, без обязательного перехода по отдельным ссылкам.
2. **Один обычный тап** по элементу/кнопке окна Windows выполняет соответствующее действие. Закрытие/сворачивание обычного окна или обычной вкладки не требует каждый раз выбирать пункт в меню и вводить пароль NEXUS. Проверять настоящий результат на Windows; не подменять его вызовом API.
3. Отдельно проверить сворачивание NEXUS Host/Windows Terminal нажатием по реальной кнопке заголовка: безопасное точное действие по окну, без ввода команд в терминал и без расширения терминальных полномочий.
4. Обычный Блокнот, не содержащий защищённых данных, виден владельцу в Live **без отдельного пароля**. Для модели и её скриншотов защищённое содержимое остаётся закрытым.
5. **Окно подтверждения не перекрывает Windows**. При действительно защищённой операции появляется компактная отдельная кнопка-ссылка; по ней владелец открывает самостоятельную форму, вводит данные только там, подтверждает решение. После подтверждения кнопка исчезает; форма закрывается сама, когда это разрешает платформа, либо даёт понятный выход. Не показывать полноэкранную накладку поверх Live.
6. **Ввод обычного текста** — отдельная компактная форма с родной клавиатурой Android; после успешной отправки исчезает. Пароли Windows/Bitwarden/2FA/платёжные секреты не передаются через модель/общий текстовый ввод.
7. STOP реально останавливает трансляцию/задачу; разрешённое владельцем выключение Windows должно либо выполниться с подтверждением результата, либо сообщить точный блокер, но не объявляться выполненным.
8. Работоспособное восстановление соединения без повторной установки, авторизации, повторного запуска завершённых тестов и без платных/дублирующих решений.

**Что НЕ входит в подтверждённый MVP:** дистанционный Windows Logon после перезагрузки, включение полностью выключенного компьютера без независимого устройства Wake-on-LAN/средства питания, гарантированная работа всех приложений. Это отдельные этапы, не представлять их как готовые.

## 3. Архитектура и границы безопасности
- Windows: NEXUS Host (по последнему онлайн-снимку версия **0.6.1-next**), независимый Supervisor/Guardian и Recovery Watchdog; связь через Cloudflare Tunnel.
- Cloudflare Worker **nexus-gateway** предоставляет OAuth/MCP, собственную страницу /live и UI-ресурс MCP Apps для встроенного виджета.
- Система подтверждений для защищённых действий использует owner-passphrase, одноразовые challenge/nonce и серверную проверку. Не получать/не раскрывать секреты через чат, инструмент MCP или логи.
- Прямая сенсорная команда проходит проверку политики Host, включая точное окно/элемент; обычное сворачивание не должно превращаться в произвольную shell-команду.
- Защита приватного содержимого: каналы кадров для владельца и модели разграничены.
- Защита GitHub main и настройки Windows Security/UAC/Defender не изменялись в описываемом этапе.

## 6. Точные дефекты и инженерные гипотезы (не выдавать гипотезы за факты)
**P0 UX: старый оверлей остаётся в ChatGPT после deploy v7.1.**
- Факт: пользователем предоставлен скриншот с большой формой поверх кадра через ~10 минут после публикации нового Gateway.
- В коде коммита 83b5df5 полноэкранный owner-overlay убран и добавлена отдельная ссылка.
- Гипотезы: активный экземпляр MCP Apps виджета сохранил старый HTML/ресурс в чате; клиент или Gateway возвращает прежний ресурс/кэш; ChatGPT продолжает ранее созданный instance; нарушена адресация resource URI; либо неработающее обновление/DOM. **Нужно измерить фактический байтовый ресурс и версию, которую получает новый виджет**, не перезапуская весь NEXUS вслепую.
- Устранение считается PASS только по свежей визуальной проверке нового ресурса на Samsung.

**P0 безопасность/корректность: логика pendingCount и confirmation.**
- В актуальном widget.mjs после исчезновения всех pendingConsents при touchConsent вызывается confirm_action с decision='allow'. **Количество запросов, равное нулю, само по себе не является доказательством разрешения именно этого запроса**: возможны cancel, expiry, исполнение другим клиентом. Проверить Host-реализацию и изменить на явную привязку к успешному подписанному решению по конкретному consentId/target; не выполнять действие после только косвенного сигнала.
- Отдельное окно /live/approvals использует window.close() после решения. На мобильных браузерах оно может не закрываться, особенно если открыто не JavaScript; это UX-поведение требует реальной проверки, не обещать безусловное автозакрытие.
- Проследить, чтобы пароли владельца/Windows и содержимое защищённых окон не попадали в MCP metadata, model-visible payload, обычные кадры или логи.

**P1 политика действий/UX:**
- Не требовать owner-passphrase для обычной вкладки Edge/Блокнота без несохранённых данных; уважать подтверждения для защищённых ресурсов и несохранённых изменений.
- Ранее диагностировались ложные блокировки безопасных git show/log команд как «boot_or_disk_destruction». Не чинить глобальным отключением защиты: нужны узкие тесты классификатора.
- Обособить пользовательский Live от функций аварийного STOP/Host off; STOP не нажимать случайно.

**P1 доступность:**
- Cloudflare 530 при запросе shutdown — фактический транспортный блокер. Разобрать независимым read-only connection_status/Guardian, если владелец разрешит возобновление. Не выполнять повторное выключение, пока пользователь не попросит.

В каждой проверке сначала ожидаемый результат, затем скрин/доказательство, только потом PASS.

Шаг F — отдельно оценить доступность Host/Recovery. Запрос выключения либо выполнен и подтверждён состоянием, либо объявлен заблокированным. Для power-on после полного shutdown сначала проверить, существует ли независимый канал включения, не обещать невозможное.
