## Что сделано (код + автотесты; на ПК не проверено)
- **Всё доступно по умолчанию:** `gui_input, process_control, run_task, browser, live_view, commands, power` = вкл.; `taskRoots` = папка профиля владельца. Профиль 0.6.0 мигрирует один раз при первом запуске (бэкап `capabilities.pre-0.6.1.json`, событие `capabilities_migrated`; запреты, blockedApps, protectedPaths, limits сохраняются; повреждённый файл не мигрирует).
- **Запрет словом:** `set_capability <ключ> false` (11 ключей) — сразу, сохраняется в `ownerBans`; `manage_app_access revoke` — блок приложения. Снятие запрета владельца — только его нажатием на `/live` (`owner_unban`).
- **Обычные действия без вопросов:** всё, что раньше давало `consent_required` (доступ к приложению, файлы вне workspace, R2/R3 команды, планы, питание при выполненных условиях, запись исполняемых файлов, системные утилиты), выполняется сразу; аудит `auto_approved`; повтор уже выполненной внешней операции не скрывается.
- **Список владельца (только `/live`):** `browser_financial`, `browser_irreversible` (удаление от его имени), `protected_file`, `protected_app`, `secret_access`, `security_page`, `security_command`, `destructive_action`, `destructive_command`, закрытие/завершение его окон и процессов, `owner_unban`. Модель получает `owner_approval_pending`, пока владелец не нажал; срок 10 мин; одноразово.
- **Команды:** Defender/UAC/SAC/BitLocker/firewall/автовход и разрушение диска/загрузки больше не «запрещено навсегда», а «решает владелец» (`security_command` / `destructive_command`); CLI менеджеров паролей → `secret_access`. Навсегда отклоняются только закодированные команды, «скачать и выполнить» и дамп учётных данных. Удаление распознаётся по имени программы и по тексту команд оболочек (PowerShell, cmd, reg, netsh…); аргументы обычных программ не сканируются.
- **AI-приложения:** Claude Desktop, ChatGPT, Antigravity, Grok и др. — обычные цели GUI; каждый набранный в них текст пишется в аудит (`agent_prompt`, секреты замаскированы). Claude Code в терминале остаётся терминалом.
- **Шлюз:** `/live` — блок «Подтверждения» (`/live/consents`, `/live/decide`: сессия по паролю + заголовок CSRF). `owner_consents`/`owner_decide` отсутствуют в каталоге модели — ChatGPT получает `unknown_tool`. Host не вводит ничего в окно «NEXUS Live View».
- **Тесты (Linux):** Host 241 pass / 0 fail (+1 skip), шлюз 34 / 0 fail; CI Windows — success.

- **Загрузки браузером NEXUS (NX-052-17/20/35):** раньше Edge NEXUS запрещал скачивание. Теперь файл скачивается в `workspace\downloads\.incoming`, затем автоматически переносится в `downloads`, получает Mark of the Web, sha256 и проверку подписи (для exe/msi/dll…); клик, начавший загрузку, сообщает о ней; `browser_tabs {action:"downloads", id}` ждёт файл; `download_verify {file, sha256, expectedSigner}` сверяет с официальными значениями, несовпадение → карантин. Лимит 2 ГБ. **Проверено:** реальный Chromium (Linux) и Edge (Windows CI).
- **Ввод текста без буфера обмена (NX-052-32):** текст набирается нажатиями клавиш (SendKeys из подписанной сборки .NET, символы вне раскладки — Unicode), буфер владельца не трогается вообще; вставка через буфер — только запасной путь, явно помеченный (`inputMethod: clipboard`). **Проверено на реальном Windows (CI):** буфер с текстом, HTML и частным форматом до и после — идентичен; в Блокноте ровно `NEXUS 0.6.1 тест {+}%^~ (x)[y] ü — ok`.

- **Отправка/публикация (решение владельца 04.11 ~10:04):** письма, сообщения, посты, регистрация отправляются по поручению владельца в чате без нажатия на телефоне (`browser_outgoing`, журнал `auto_approved`); удаление от его имени осталось в списке владельца. Без поручения модель не отправляет (инструкция в каталоге); Host отличить поручение от внедрённого текста не может — это решение владельца.

## Известные ограничения (честно)
- Распознавание «безвозвратного удаления» в произвольном скрипте — эвристика по тексту: программа (`node -e`, `python`) может удалить файл, не попав в список владельца. Гарантия списка полная для структурных инструментов (браузер, файлы, GUI, питание, приложения), для произвольного кода — частичная.
- Подтверждение на `/live` защищает от внедрённого текста, пока владелец сам не открыл `/live` в браузере ПК, которым управляет NEXUS: Host блокирует ввод в окно с заголовком «NEXUS Live View», но заголовок — недоверенные данные. Рекомендация: открывать `/live` на телефоне.
- NX-03/13/19/21/26 — причина неизвестна, нужны данные с ПК владельца; 0.6.1 соберёт их сама после установки (команды и диагностика теперь без настроек), исправления — следующей сборкой.
- Не решается кодом: включение выключенного ПК (нужно отдельное устройство в LAN, Ethernet отключён) и вход после перезагрузки (CRD/RDP один раз).
- Ввод клавишами на ПК владельца ещё не проверялся (раскладки, IME); при сбое Host сам переходит на вставку через буфер и сообщает об этом.
