# NEXUS 0.5.1 — единый пакет исправлений по живой приёмке (для Claude)
**Согласовано владельцем 02.11.2026. Разработку вести в `experiment/nexus-0.5.1-cleanup-stop-20261102`.**
**ВНИМАНИЕ:** это задача на разработку и автоматические тесты; **не устанавливать** на Windows, не трогать Gateway/production/main без отдельной команды на поставку. Не использовать TRINITY.

## Проверенный чекпоинт — не начинать заново
- На ПК Host NEXUS **0.5.0**. В этой сессии ChatGPT вызвал `get_capabilities` и `host_diagnostics`: `live_view=false`, `gui_input=false`, Host online, config `fileError=null`. Никаких дополнительных изменений на ПК не выполнялось.
- Живая приёмка 0.5.0: Host/34 доступных модели инструмента, Gateway online, встроенный `watch_nexus` и поток кадров (274 кадра), мышь/клавиатура/Notepad/Calculator — PASS; на чужой вкладке Notepad `consent_required` и `confirm_action(cancel)` — PASS, пользовательские вкладки сохранены.
- НЕДОРАБОТКИ из приёмки: `focus_window` Notepad `focused=false`, хотя клик помогает; собственная изменённая scratch-вкладка вызывает диалог сохранения; у Calculator `createdByNexus.windows=[]`; курсор именно *в live-клиенте* не подтверждён; браузер был отключён, Edge cleanup в тестах вызывает вопросы; штатная кнопка Stop ChatGPT → прекращение работы NEXUS НЕ проверена.
- **Новый воспроизведённый пользователем дефект:** после нажатия Stop на наблюдательном экране Live View оставался работать; после обычного финального отчёта Live View 0.5.0 оставался `live_view=true`. Сейчас отключено; нужна автоматическая гарантия, а не ручной Stop.
- Исходники и отчёт 0.5.0 уже в репозитории: `windows-pc-agent-lab/NEXUS-0.5.0-REPORT.md`, `NEXUS-0.5.0-ACCEPTANCE.md`; использовать рабочий код, не переписывать систему и не повторять всю историческую приёмку.

## ОБЯЗАТЕЛЬНАЯ политика: «пришёл → выполнил → убрал за собой → отчитался»

### A. Live View lifecycle (P0, главное)
1. **Начало работы с настоящим рабочим столом Windows:** Live View включается автоматически **до первого действия мышью/клавиатурой/управления окнами**, чтобы владелец мог наблюдать. При простой беседе, чтении логов/API без GUI захват экрана НЕ запускать. Если владелец явно выключил Live View или не хочет трансляцию — уважать это.
2. **Во время действительной GUI-задачи** поток обновляется непрерывно, включая переключение между окнами. Не нужно открывать отдельные параллельные окна или вкладки просмотра; использовать уже внедрённый ChatGPT-виджет и существующий fallback `/live`. Не добавлять новые STOP-кнопки: владелец уже имеет штатный Stop в ChatGPT.
3. **Завершение КАЖДОЙ GUI-задачи (100%, даже если остались окна просмотра):** автоматически прекратить генерацию кадров на Host, установить `live_view=false` (если не зафиксировано явное требование владельца оставить), проверить факт остановки, только затем выдать финальный отчёт. Активный виджет/вкладка в ChatGPT НЕ должны сами по себе удерживать захват после окончания задачи. Нет зрителя → нет кадров.
4. **Любая ошибка, таймаут, обрыв соединения, остановка ответа ChatGPT, исчезновение клиента или закрытие сессии:** fail-safe остановка экрана и GUI-операций, а не вечный оставшийся `live_view=true`. Сделать независимый от доброй воли модели lifecycle на Host/Gateway: ограниченный срок аренды GUI-сессии (lease), heartbeat **от активной работы**, watchdog/TTL, отмена pending jobs, освобождение ресурсов. Сам просмотр кадров не должен бесконечно обновлять lease выполнения задачи.
5. **Штатная кнопка Stop ChatGPT:** выяснить, передаёт ли клиент событие остановки по MCP, abort HTTP/закрытие stream, lifecycle виджета. Если реально нет независимого сигнала, **не обещать мгновенный STOP**; сделать гарантированный короткий предел автоматического прекращения через lease (целевой максимум 10–15 с после потери активной работы, уточнить по безопасной технической реализации) и явно сообщить измеренную задержку. Stop должен прекращать не только визуализацию, но и дальнейшие операции, которые агент успел поставить в очередь (без закрытия чужих документов).
6. После завершения, STOP или ошибки: не делать автоматическое `live_view=true` повторно без новой GUI-задачи. Завершение рендеринга/ответа не должно оставлять активный поток.

### B. Уборка окон и вкладок (P0)
1. **Открыл собственное окно/вкладку → выполнил часть работы → закрыл**, если больше не используется. Не накапливать много окон; обычно одно, два или больше — только при реально необходимой одновременной работе.
2. На выходе из задачи (успех/ошибка/Stop) закрыть только NEXUS-created окна/вкладки/браузерные временные вкладки и ненужные собственные процессы. **Никогда не закрывать пользовательские или неизвестные окна/вкладки без точечного согласия**, даже если они расположены в том же процессе Notepad.
3. В Windows 11 Notepad собственная `.nexus-scratch` вкладка после тестового ввода должна закрываться автоматически, без зависшего Save/Don't save. Допустимо автономно «не сохранять» только удостоверенно собственный одноразовый документ, который пользователь не редактировал; при неясном владении или возможных пользовательских изменениях — не уничтожать данные, попросить решение. Проверять вкладку по идентичности, а не только PID или имени.
4. Исправить `createdByNexus.windows=[]` у Calculator, отслеживать свои HWND/процессы при асинхронном открытии; обеспечить корректную идентификацию закрываемой цели и отсутствие влияния на чужие окна.
5. Убирать собственные Edge и дочерние процессы с отладочным портом, когда браузерная задача закончена, включая error/Stop, без убийства пользовательских Edge. Сохранять защищённую границу профиля.

### C. Прочие выявленные дефекты 0.5.0 (P1 — в том же пакете)
- `focus_window` на Windows владельца: точно определить, почему `focused=false`; проверять HWND, использовать безопасный fallback, не вводить в чужой процесс, возвращать реальное состояние.
- Отображение курсора в живых кадрах: подтверждение именно в ChatGPT web/Android (если без пользователя нельзя — готовый одноразовый шаг приёмки; не заявлять PASS из одних unit-тестов).
- Провести браузерный smoke в изолированном профиле с разрешением владельца **после установки**, проверить очистку процессов. Управление Windows Settings расширять через существующий механизм allowlist/consent, без обхода системных запретов и отключения защиты.
- Сохранять автономию пользователя: **не спрашивать согласие на каждый клик**. Запросы только для обоснованно опасных/необратимых действий (платёж, удаление чужих данных, секреты, сомнительные сайты) или существующей защиты чужих вкладок. Уже действующее право управлять ПК не должно требовать повторного одобрения каждой операции.

## Конкретная техническая приёмка и критерии PASS
Автоматические CI на Windows + Linux + Gateway, включая тестируемые lifecycle/lease/timeout, cancel, ownership/cleanup Notepad, Calculator, Edge без пользовательских файлов. Не запускать real-GUI тесты от обычного `node --test` без явного имени `*-real*`/отдельной метки. Не создавать бесконечный Java/Edge child.
В одной живой интеграционной проверке после установки:
- Запуск GUI-задачи → Live View включён до первого реального взаимодействия.
- Несколько действий подряд → Live View продолжает работать, число окон не растёт бесконтрольно.
- Финальный отчёт → `live_view=false`, кадров больше нет, свои вкладки закрыты, `gui_input=false` (если больше не нужен), пользовательские вкладки не тронуты.
- Прерывание задачи штатной кнопкой ChatGPT Stop → замерена задержка прекращения Host-контроля/потока; реальный PASS только если Host перестал выполнять операции и остановил захват. Если клиент не передаёт сигнал, зафиксировать правдивый worst-case TTL, а не «Stop гарантированно мгновенный».
- Сбой/отключение туннеля → watchdog отключает захват, никаких незавершённых фоновых процессов и чужих закрытых окон.
- Переключение между Notepad/Calculator, закр. только собственных scratch и окон; чужие документы — без изменений.
- Нет новой платной инфраструктуры, постоянных записей кадров, секретов в логах или новых кнопок STOP.
