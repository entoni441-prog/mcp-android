# NEXUS — инженерные решения и регламент автономной работы
Дата: 2026-11-01. Документ для продолжения работы ChatGPT без зависимости от доступности Claude.

## Цель
Работающий, управляемый с обычного ChatGPT доступ к собственному Windows ПК пользователя для настройки, разработки и автоматизации. Долгосрочно: собственные локальные альтернативы облачной браузерной автоматизации (TinyFish) и хостингу репозиториев/сборок (GitHub), снижение зависимости от платных лимитов. При этом не создавать лишние инструменты, если существующие уже решают задачу.

## Подтверждённые архитектурные решения
- **MCP прежде новой очереди.** В наличии действующий паттерн Chat Router: ChatGPT ↔ MCP с OAuth ↔ Cloudflare Worker. Тот же подход предпочтителен для Windows, пока не доказано обратное. Не создавать параллельный самописный механизм D1-подписей/очередей и хранение результатов в D1 без обоснования.
- **Локальный исполняющий узел — NEXUS Host v0.1.0** на Windows: Node.js `server.mjs`, Streamable HTTP MCP на `127.0.0.1:8765/mcp`, локальный Bearer-токен, набор фиксированных инструментов (get_status, list_dir, read_text, make_dir, write_text, open_app). Это уже написано Claude в **отдельной** ветке `experiment/nexus-host-mcp-20261101`, коммит `afa4433ccc9dd78657ba58406267224e487273d4`.
- **На реальном ПК результат уже есть:** из предоставленных пользователем скриншотов и отчёта локальной сессии Claude Code — сервер запустился в Windows, запрос без токена вернул HTTP 401, тестированы все шесть инструментов, открытие Notepad подтверждено видимым окном. Разграничение доказательств: это результат локальной сессии, **не прямой удалённый вызов из данного ChatGPT**.
- **Windows Smart App Control:** доставленная из интернета `.cmd` обёртка была заблокирована, что не означает неисправность Node/MCP-логики. Нативный `node.exe` + `.mjs` успешно запустился на реальном Windows по данным локальной сессии. Не отключать защиту. PowerShell UI Automation при App Control может иметь ограничения; проверять, не выдавать гипотезу за факт.
- **Cloudflare Entoni MCP доступен из обычного ChatGPT:** на 2026-11-01 успешно прочитаны существующие Workers и список Tunnels; API имеет операцию загрузки Worker Module, но **разрешение записи/деплоя ещё не подтверждено**. На момент проверки в аккаунте список Cloudflare Tunnels пуст. Не требовать `wrangler login` или новой авторизации до реального подтверждения, что уже доступного API недостаточно.
- **OAuth для этапа 2**: использовать существующий шаблон `relay/mcp/` из рабочего Chat Router (workers-oauth-provider, GitHub-вход, ограничение владельцем) как референс. Проверить его фактическую доступность и текущие настройки перед копированием. **Cloudflare Tunnel не заменяет OAuth и контроль полномочий**; локальный доступ ограничить доверенными операциями. Перед сетевым подключением сделать security-review с fail-closed.
- **Не трогать production/main или рабочую v2-систему.** Историческая v3-ветка `experiment/windows-pc-agent-v3-control-20261031` содержит промежуточный прототип, CI и чекпоинты. Она не является текущей основной разработкой; активная ветка Claude — `experiment/nexus-host-mcp-20261101`. Прежнее отклонение публикации исполняемых v3 компонентов продолжает действовать; не обходить его изменением названий, упаковки или сервиса.

## Правила решений и самоисправления ChatGPT
1. Сформулировать **проверяемый конечный результат** до кода. Отличать локальную работу, CI, состояние облака и фактическую доступность **из обычного чата**.
2. Перед разработкой читать **последний реальный чекпоинт и активную ветку**, сверять живые инструменты/права. Отсутствующий коннектор в текущей сессии ≠ отсутствующий сервис.
3. При блокере/отказе/повторяющемся цикле — остановить тупиковую линию и сравнить минимум две **принципиально отличные разрешённые** архитектуры, включая уже существующие стандарты (MCP/OAuth/API, Git, Windows).
4. Не считать чужой вывод истинным по авторитету: Claude и ChatGPT независимо проверяют факты, риски и гипотезы; при отсутствии Claude выполнять ту же альтернативную проверку самому.
5. Сначала самый короткий end-to-end тест на **реальной целевой среде**, затем усложнение. Unit/CI — поддержка, а не доказательство работоспособности на ПК пользователя.
6. Проверять **полномочия существующих инструментов** до просьбы о новой авторизации, ручном действии, подписке, регистрации, установке или расходе платного кредита.
7. Избегать самостоятельных дублей готовых возможностей; предпочитать простой поддерживаемый компонент с чёткими границами прав.
8. За каждый практический этап фиксировать: **выполнено / подтверждение / текущий блокер / один следующий шаг**, не путать план с фактом. Документы помогают продолжить, но сами не являются результатом.
9. Без оплаты, раскрытия ключей, отключения защиты, повышения привилегий, изменения production/main и рабочих служб без отдельного разрешения. Не распространять локальный Bearer-токен; не публиковать порт NEXUS напрямую в интернет.
10. Пользователь не должен повторять уже проверенные действия только потому, что сменился чат или модель. При наличии доступного API выполнять безопасную работу самостоятельно.

## Важная коррекция прошлого подхода
Ранее ChatGPT потратил время на v3, отдельные CI и установочный `.cmd` вместо раннего прямого рассмотрения MCP и реальной Windows-среды. Урок: **не оптимизировать прототип, который не приближает к end-to-end**, и не требовать ручной работы до проверки доступных инструментов.
