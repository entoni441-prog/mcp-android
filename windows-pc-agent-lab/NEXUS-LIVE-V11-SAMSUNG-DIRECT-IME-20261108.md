## Незавершённый пользовательский сценарий
В Live v10.1 после нажатия на обычное текстовое поле Блокнота появляется `Ввести текст ↗` и отдельный ручной `Отправить`. Пользователь требует: **коснулся поля в Live → открылась штатная клавиатура Samsung → ввёл или стёр текст непосредственно в Windows без дополнительной отправки**. Аналогично для обычных Edit, Document, ComboBox в разрешённых приложениях.

## Реализация в Gateway v11
- После возвращённого Host `mouse_action` со `done:true` и `target.control` равным Edit/Document/ComboBox, `target.isPassword === false` и отсутствием секретных имён, Live автоматически показывает компактный Android HTML IME input и пытается поставить на него фокус. После async MCP ответа Android WebView может потребовать дополнительное пользовательское касание; в таком случае видна одна резервная кнопка `⌨ Клавиатура` на той же карточке Live. Картинка Windows не перекрывается.
- События `input` / `compositionstart` / `compositionend`, `beforeinput` / `keydown` транслируются **в выбранный реальный Windows caret** через существующий `keyboard_action`: Unicode, сочетание последовательных букв, окончание composition, замена конца введённого слова, удаление Backspace, Enter/Tab и базовая навигация. Кнопка `Отправить` более не нужна; кнопка ↵ отвечает за Enter.
- Для выравнивания Android IME и Windows используется **локальная зеркальная строка только вновь введённого текста, НЕ текст документа Windows**. `planImeSuffixEdit` вычисляет добавление/удаление суффикса; ввод/удаление, меняющее середину локального proxy, отклоняется. Реальный курсор перемещается касанием документа Windows или клавишами навигации.
- Операции `keyboard_action` сериализованы, объединяют быстрый последовательный ввод (debounce 130 мс); при неизвестном результате очередь блокируется и **никаких автоматических повторов нет**. Двойные события пустого Backspace и Enter дедуплицируются.
- На каждом действии реальный Host заново проверяет foreground process, разрешённое приложение и `isPassword`. Новая функция **не применяет ввод в PIN/password/OTP, терминалы и прочие защищённые поля**; эти существующие политики не ослаблены.
- При нажатии не на обычное текстовое поле IME скрывается. При STOP/PAUSE отключается. Ввод без включённого Owner Touch невозможен.
- Максимальный буфер одного редактирования — 2000 символов (меньше лимита Host keyboard_action 4000). Для длинных документов можно переводить строку Enter или заново выбирать поле.
- Новый уникальный `ui://nexus/live-view-v11.html`, чтобы ChatGPT не показал cached v10 карточку. Старые URI остаются в списке для совместимости; **это не механизм rollback**. Каталоги Host/Gateway остаются совпадающими.

## Что НЕ проверено
- **Появляется ли клавиатура Samsung автоматически из ChatGPT MCP App после асинхронного ответа Host.** Это зависит от фокуса Android/WebView. Если Android блокирует автоподнятие IME, единственный fallback — нажать `⌨ Клавиатура` прямо в той же карточке; это меньше действий, чем ручная отправка.
- Насколько удобно вводить многострочный текст и удалять существующий текст в Блокноте при долгих сессиях. Могут потребоваться UX-итерации после одного реального теста.
- Работа с другими обычными приложениями зависит от уже существующей Host allowlist и доступного UIA-типа поля; не заявлять универсальный PASS без проверки.
