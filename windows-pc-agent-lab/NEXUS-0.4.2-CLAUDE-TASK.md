# NEXUS 0.4.2 — финальное ТЗ для Claude (согласовано владельцем 01.11.2026)

**Разработка разрешена в этой экспериментальной ветке. Никаких изменений рабочей 0.4.1 на ПК, main, посторонних Workers или production без отдельного согласия на поставку.**

## Исходный чекпоинт

NEXUS 0.4.1: 27 MCP-инструментов доступны, сквозной Windows GUI и передача PNG подтверждены. В фазе B успешны включение/выключение `gui_input` без перезапуска, текстовый ввод, мышь, UI Automation, скриншоты и отказ `target_not_allowed` вне разрешённой области. После фазы B `gui_input=false`.

Замечания: `focus_window` вернул `focused=false`, хотя клик внутри Notepad установил фокус; короткие `pc_offline`; тест создал вкладку в существующем окне Notepad рядом с пользовательскими файлами и закрыл окно. Впоследствии ChatGPT заново открыл Notepad и через `inspect_ui` подтвердил, что пользовательские вкладки восстановлены, в том числе вкладка со статусом «Изменено». Содержимое пользовательских файлов не читалось, сохранение не выполнялось.

## 1. Вкладки, окна и согласие владельца (P0)

**Ключевая окончательная правка:** НЕ вводить общий запрет закрытия чужих окон и вкладок. ChatGPT **может их закрывать по явному согласию владельца** на конкретное действие. Если вкладку/окно создал сам агент для теста и там нет пользовательской работы, их можно закрыть автономно.

- Различать приложение/процесс, окно и отдельную вкладку: в Windows 11 Notepad `open_app(notepad)` может показать уже существующее окно с пользовательскими вкладками, а не пустой Блокнот.
- Отслеживать вкладки, созданные NEXUS в конкретной сессии, отдельно от ранее существовавших/неизвестных. Не считать весь процесс «своим» из-за одной тестовой вкладки.
- Любая команда закрытия пользовательской или неопределённой вкладки/окна (`Ctrl+W`, `Alt+F4`, X, `process_action(close)`, аналогичные маршруты) должна требовать **точечного подтверждения владельца до выполнения**. После одобрения разрешать действие, а не блокировать навсегда.
- При несохранённых изменениях отдельно запрашивать решение «сохранить/не сохранять/отмена» для соответствующего пользовательского документа. Не выбирать самовольно потерю данных.
- Учитывать пути обхода защиты через мышь, клавиатуру, меню и закрытие процесса. При невозможности надёжного перехвата — документировать ограничения, не выдавать частичную защиту за полную.
- Для GUI-тестов создавать отдельную чистую вкладку/документ и закрывать **только её**; не менять и не закрывать другие вкладки. Проверять состояние до/после.
- Другими возможностями управления пользователю не мешать. Принцип: **автономия по умолчанию, согласование рискованных действий**, а не новые произвольные запреты.

## 2. Надёжный фокус (P0)

- Диагностировать на реальном Windows причину `focus_window → focused=false`: foreground permissions, hwnd/pid, UIA/Java/PowerShell.
- Короткое нажатие `Alt` перед фокусировкой — только гипотеза, требующая проверки, не безусловный патч.
- Добавить контролируемый fallback с проверкой фактического foreground HWND/PID. Не отправлять ввод, если он рискует попасть в чужое окно.
- Покрыть тестом Windows, включая несколько вкладок Notepad и конкурирующее активное окно.

## 3. Временный `pc_offline` (P0)

- Сопоставить логи Host, cloudflared, Gateway, KV-регистрацию и активность локальной сессии Claude Code; разделить доказанные причины и гипотезы.
- Диагностика без секретов и содержимого экрана/документов, проверяемая устойчивость, минимум изменений.
- Не повторять бессмысленно deploy/restart; не трогать существующий Gateway до проверки изменения.

## 4. Live View для владельца на телефоне и компьютере (новое требование)

Пользователь хочет наблюдать действия ChatGPT на его Windows в реальном времени, как LIVE у TinyFish: экран, движение мыши, изменения интерфейса — **вне зависимости от того, на телефоне или ПК открыт чат**. Сейчас `capture_screen` — отдельные скриншоты, а не поток.

- Исследовать, допускает ли текущий ChatGPT/плагины встроенный Live View. Если нет — не обещать встроенное окно, предложить защищённый внешний просмотр по ссылке из чата с максимально похожим UX.
- Просмотр должен показывать последовательность кадров и позицию курсора; разумная частота кадров/качество, умеренный трафик; понятный статус LIVE.
- Доступ только владельцу с аутентификацией. Видимый индикатор активного просмотра, пауза и мгновенный STOP, без фоновой записи/архива по умолчанию. Экран может содержать пароли и личные данные — не допускать открытых публичных стримов и раскрытия секретов.
- Предпочесть существующие NEXUS Host, Gateway и Cloudflare; никаких новых платных подписок.
- Если реализация Live View увеличивает риск или сильно расширяет 0.4.2, подготовить проверенную архитектуру и отдельный этап/MVP; **не откладывать P0-исправления ради стриминга**. Указать явно, что уже работает и что лишь предложено.

## Порядок работы и критерии приёмки

1. Разработка/тесты в `experiment/nexus-0.4.2-20261101`; основа — проверенная 0.4.1. Рабочий Windows Host 0.4.1 не менять.
2. Тесты на Windows/Ubuntu/Gateway: владельческая/чужая вкладка, несохранённые изменения, закрытие через разные механизмы, согласие на конкретное закрытие, отсутствие обходов, фокус/fallback, диагностика offline. Не использовать для тестов реальные несохранённые файлы пользователя.
3. Сохранить существующий `Always ask` и переключатель `gui_input`. Никаких неконтролируемых изменений доступов.
4. Приготовить отчёт: ветка, commit SHA, точные файлы, результаты CI и ограничения. План доставки: backup 0.4.1, SHA-256, одна активация, smoke, Gateway только после Host PASS, rollback. **Не ставить 0.4.2 на ПК без отдельного решения владельца.**
5. Не повторять уже пройденную фазу B без конкретной необходимости.

Итоговый ориентир: ChatGPT автономно управляет ПК, но владелец видит действия и решает, разрешать ли закрытие своих данных. Никаких новых бессмысленных ручных действий владельца.
