## 2. Какие действия владелец ожидает в финале

1. NEXUS Live появляется в **самом диалоге ChatGPT** (на Samsung), а не открывается каждый раз браузер по внешней ссылке; доступно PiP/полный экран, Pause, STOP; просмотр кадра и фактическое управление должны соответствовать друг другу.
2. Касание изображения Windows = одно обычное нажатие по целевому элементу. Двойное касание = один double-click; без тройного срабатывания, командных обходных путей, лишнего выбора PID или отдельной панели «Окна». Отображать действительный курсор.
3. Открыть, активировать, свернуть, восстановить и закрыть обычное окно/вкладку (Проводник, Калькулятор, Блокнот, обычный Edge). Особый реальный тест: **свернуть NEXUS Host / Terminal прямым касанием штатной кнопки заголовка**; если окно имеет нестандартный заголовок — диагностировать native/UIA hit-test, а не ослаблять политику shell.
4. Обычный Блокнот — не «секретный» по одному имени программы. Владелец видит его в Live без дополнительного пароля; модель не получает содержимое защищённых окон через capture_screen. Чужой несохранённый текст не терять: если есть unsaved prompt — сохранить/не сохранять только согласно конкретному выбору владельца.
5. При выборе **обычного** текстового поля появляется отдельная компактная форма для текста со штатной клавиатурой Samsung; форма не должна лежать поверх видеокадра и мешать касаниям. После подтверждённой отправки очищается/исчезает. Вводить секреты через этот механизм запрещено; для защищённого ввода отдельный owner-only маршрут.
6. Для защищённых действий (пароли, платежи, Windows security, необратимое удаление, приватные ресурсы) — уведомление/кнопка-ссылка **отдельно от экрана**. По нажатию владелец сам открывает защищённую форму, вводит свой пароль и принимает конкретное решение. После успешного решения уведомление исчезает. Пароль/nonce не попадают в model/tools/calls/logs. Обычные действия без этого.
7. Host + Gateway + Live должны корректно восстанавливать соединение после локального сбоя/перезапуска. Не терять owner pause/STOP; не перепутать активный сеанс с устаревшим.
8. Power/shutdown/lock/restart управляются отдельной подтверждённой функцией с проверкой реальных предусловий. Никогда не обещать «выключен», если нет подтверждения. Приоритет — не лишить владельца удалённого входа после перезагрузки.
9. При тестировании новых функций не ломать уже принятые Calculator, Explorer, text typing, Host restart/recovery, Gateway OAuth, owner secrets, защиту main. Если сломано — откат строго в проверенную сборку.

## 5. Точные ошибки и предположения, которые нужно различать

**Подтверждено:**
- Накладывающаяся на изображение Windows форма owner approvals присутствовала на Samsung до v7.1 и на скриншоте после v7.1.
- Встроенная Live-карточка в чате действительно отображает Windows, но сам факт наличия кадра ≠ возможность корректного управления окнами касаниями.
- Реальный запрошенный сценарий закрытия обычного Edge не был завершён, один consent висел. Заявленный UX «без пароля для обычного» не реализован или нарушается действующей политикой Host.
- Первую попытку wrangler deploy заблокировало отсутствие npm dependency @cloudflare/workers-oauth-provider; после npm install 35 пакетов ошибка устранена. Последующие deploy были exit 0.
- Локальные автоматические тесты Gateway/Live 71/71 PASS перед публикацией v7.1. Это не Android E2E.
- Shutdown через NEXUS не прошёл при edge 530. Позднее Host снова reachable. Выключение компьютера не подтверждено.

**Гипотезы — требующие диагностики:**
- stale MCP App widget / resource cache: v7.1 изменён код, но прежний URI ui://nexus/live-view-v7.html мог остаться в активной карточке/кеше; видимая форма могла относиться к ранее созданной Live-карточке. Не объявлять эту версию ошибки доказанной.
- Адаптивная вёрстка старого panel могла быть не заменена в client-side widget несмотря на обновлённый Worker; проверить bytes/resources/read, version/URI, повторный fresh widget, mobile UI. Не ограничиваться /health.
- Permission gating для Edge/Notepad может выполняться на Host независимо от формы Gateway. Смена CSS не устранит причину лишнего consent. Нужно отделить UI от policy и проверить точное ownership/unsaved состояние вкладки.
- Нестандартный заголовок Terminal может не предоставлять native minimize proof; при отказе исследовать hit-test UIA/Win32, не эмулировать shell keystrokes и не понижать защиту.

## 6. Чего НЕ делать

- Не менять main, текущий рабочий Host, production Gateway, Windows security или OAuth без отдельного однозначного согласования с владельцем. Существующий deploy v7.1 — уже факт; следующий deploy не требуется только потому, что тесты «зелёные».
- Не отключать защиту паролей, не просить секреты в чат, не копировать passphrase/PIN в logs, model tools или GitHub.
- Не переделывать работающие функции, не повторять старые интеграции/установки без причины, не запускать GUI по кругу.
- Не заменять direct touch дополнительными «Окна ▾»/PID selector и не выдавать кодовую реализацию за реальный PASS.
- Не повторять shutdown/reboot без нового явного поручения пользователя. Power и сохранность удалённого доступа имеют повышенный риск.
- Не делать force-push, hard reset или rollback, если параллельные агенты могли внести изменения.
- Не добавлять подписки, платные сервисы и ненужные внешние зависимости.

## 11. Дополнение к handoff: Google Flow / обычный Edge — новый функциональный блокер (сообщено 08.11.2026)

**Приоритет:** исправление NEXUS browser/Edge в рамках той же приёмки; Google Flow нужен владельцу как реальный рабочий инструмент. См. подробное ТЗ: [NEXUS-EDGE-GOOGLE-FLOW-RECOVERY-20261108.md](NEXUS-EDGE-GOOGLE-FLOW-RECOVERY-20261108.md).

Из другого чата поступил отчёт: Google Flow удалось открыть через NEXUS, но Google отказал в авторизации во встроенном браузере, назвав его небезопасным. В обычном Microsoft Edge вход открылся, однако NEXUS не смог надёжно получить экран/элементы окна для выбора аккаунта. Одновременно активна другая сессия, её не трогали. Вход не завершён, пароль не запрашивался, одна созданная агентом вкладка Edge не закрылась автоматически. **Это сообщённое состояние из другого чата, а не вновь подтверждённая диагностика.**

**Требуемая работа Claude:** сначала read-only проверка активной сессии, окна/вкладки Edge, image capture vs privacy masking, UIA/browser/CDP, целевого элемента и ownership. Затем адресный минимальный fix без обхода ограничений Google и без снижения безопасности. Стандартный Edge — основной путь для Google login; MFA/пароль вводятся владельцем в официальном интерфейсе. Последний этап — один достоверный клик выбора аккаунта, подтверждение фактического входа в Google Flow и уборка только созданных NEXUS окон/вкладок. Ни один пункт не считать PASS без реальной проверки на Samsung/Windows.

**Обновление критериев приёмки:** браузерный Google Flow сценарий и cleanup Edge — отдельные обязательные E2E критерии наряду с минимизацией окон и независимыми подтверждениями. Нельзя считать общую приёмку NEXUS завершённой, пока этот инструмент не работает (или не зафиксирован конкретный внешний блокер).

**Ограничения:** не повторять неработающий Google login внутри заблокированного embedded browser; не обходить защиту Google; не вмешиваться в параллельную сессию; не менять main/production без разрешения.
