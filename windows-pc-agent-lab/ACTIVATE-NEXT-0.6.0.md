## Правило ошибок и отката (решение владельца 03.11.2026 ~11:28)
Порядок при любой ошибке: **диагностика → безопасное исправление → повторная проверка → продолжение**. Локальная устранимая ошибка не останавливает весь процесс: остальные независимые шаги продолжаются, ошибка фиксируется в отчёте.

**1. Диагностика (всегда первой).** Установить факт и причину: повторить проверку один раз (исключить случайный сбой), собрать вывод команды, `/healthz`, `host_diagnostics`, журнал Host, состояние процесса. Определить, вызвана ли ошибка установкой (новые файлы/настройки) или существовала до неё / внешняя (сеть, Cloudflare, занятое окно, ограничение тестовой среды).

**2. Допустимые исправления без владельца** — только то, что возвращает установку к задуманному виду, не меняя кода сборки и защиты:
- повторное копирование файла, не прошедшего проверку манифеста, из сборки `0dbd067`;
- повторный запуск Host через Планировщик; освобождение занятого порта процессом прежнего Host NEXUS;
- добавление отсутствующих ключей `capabilities.json` со значениями по умолчанию (включённые владельцем переключатели не менять);
- повтор smoke-шага после устранения внешней причины (например, закрыть окно, созданное NEXUS);
- для F: повторный `wrangler deploy` той же сборки после сетевой/временной ошибки.
**Не допускается** без владельца: правка исходного кода на ПК (дефект кода → исправление в ветке + CI + новая сборка), изменение Smart App Control / Defender / UAC / Firewall, секретов, `main`, чужих окон и файлов, включение переключателей владельца.
Предел: **не более 2 попыток исправления на одну ошибку**; затем — зафиксировать блокер (`BLOCKED` с фактами), продолжить независимые безопасные шаги; при условиях шага 4 — аварийный откат компонента, иначе шаг 5.

**3. Повторная проверка.** После исправления — тот же шаг проверки заново. PASS → продолжение. В отчёте: исходная ошибка, причина, исправление, повторный результат.

**4. Аварийный автооткат — только при всех условиях одновременно:**
- неисправность **подтверждена** (воспроизводится после повторной проверки);
- **вызвана установкой** (до установки этой неисправности не было);
- допустимые исправления не помогли или их нет;
- безопасно продолжать нельзя: затронутый компонент неработоспособен (Host не запускается или не отвечает, шлюз не отвечает / `connection_status` не `online`, ChatGPT потерял доступ к ранее работавшим функциям, D/E мешают входу или работе ПК).
Тогда откатывается **только затронутый компонент** (Host, шлюз, D или E) по процедуре выше; остальные установленные компоненты остаются. Автооткат одного компонента — не более одного раза; если откат сам не удался — стоп этого компонента, ничего больше не менять, отчёт владельцу.

**Не являются основанием для отката:** неподтверждённый FAIL (не воспроизвёлся), ошибка smoke-теста при работающем компоненте, устранимый дефект, дефект отдельного инструмента при работающем Host (инструмент помечается FAIL, исправление — в ветке), внешняя причина. Такие ошибки → отчёт и исправление в следующей сборке.

**5. Решение владельца** требуется только если: дефект кода делает компонент непригодным, но откат невозможен/неудачен; исправление требует действий из списка «не допускается»; ошибка затрагивает данные или безопасность владельца. Тогда — один конкретный вопрос с фактами и вариантами.

**После успешной установки** (физическая приёмка, работа): та же схема — диагностика, допустимые исправления, отчёт. Ручной откат предлагается владельцу только по пункту 5.

**Что правило не отменяет:** несохранённые изменения владельца сохраняются и не перезаписываются (A.1); STOP владельца обязателен; при риске нарушения безопасности или системной угрозе — по разделу «Ошибки во время приёмки» в `NEXUS-NEXT-ACCEPTANCE.md` (п. 6–7); без разрешения D/E/F не выполняются.
