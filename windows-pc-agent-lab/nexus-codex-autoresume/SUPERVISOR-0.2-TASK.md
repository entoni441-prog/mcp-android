## Objective
Extend existing `controller.mjs` and create independent `supervisor.mjs` plus `supervisor.test.mjs`, README update. Prove autonomous recovery of an explicitly authorized one-task Codex CLI job **when the independent controller process crashes**, not merely when its Codex child crashes. Use existing manifest and exact recorded Codex thread UUID, durable checkpoint/claim; never blindly retry an uncertain operation.

A real controller crash may leave its Codex CLI child alive. Critically, do **not** launch resume while that child may still act. Monitor its recorded PID and process identity. For cross-platform testing use precise proc lifecycle; on Windows for real process identity, exact child process executable, parent relation and creation time when available. If process is alive, wait with bounded deadline for natural exit; on uncertainty or timeout, STOP with explicit reason, leave everything untouched. Do not kill arbitrary/external PIDs. A verified-exited child and previously durable thread UUID permit a single guarded resume, but only with an idempotent task that independently checks its completion marker before acting.

## Implementation design constraints

1. `supervisor.mjs run <manifest.json>` is the **only** entrypoint for this mode. Spawn `controller.mjs run <manifest>` as a child process. Supervisor itself must live in a separate Node process, not the same controller runtime. Persist durable nonsecret supervisor state under the manifest's dedicated stateDirectory. Guard one-task exclusivity. Capture controller PID and process launch identity, reconcile after crash, and never execute duplicate concurrent controllers. The supervisor may spawn `controller.mjs recover <manifest>` once only if all recovery prerequisites are met, else fail-closed STOP. If supervisor itself dies, leave durable STOP/claim; no unsafe unattended relaunch without separate recovery controller.
2. Change `controller.mjs` to support `recover` **with externally supervised evidence only**, while preserving original `run` behavior and strict safety checks. Old permanent `owner.json` claim remains; allow recover only once under unique supervisor claim + exact original taskId and immutable manifest digest, no other owner. Persist `originalControllerPid` or equivalent, exact UUID, child PID and launch identity. Use atomic durable state and monotonic resume budget, e.g. reserve attempt before launch. Never re-run initial prompt after crash, never use `--last`. Refuse resume if child alive, uncertain, missing UUID, malformed marker, failed turn or owner STOP, mismatched SHA/branch/manifest, or active approval boundary. If completionFile is valid and belongs to this taskId, finalize without replay. Existing maxResumes=1 applies **across all processes**; if consumed, STOP.
3. Avoid TOCTOU where practical: after verifying child dead, re-check before spawning and confirm test-only process absence. Do not trust only a PID: process may be reused; record creation time or start tick when viable. For Windows use CIM read-only process identity. If creation-time certainty cannot be established, classify uncertainty and STOP (report rather than risk). On Linux use proc starttime or process liveness with additional identity evidence.
4. Store no prompts, raw Codex stdout/events, environment, tokens, credentials, full CLI command line. State/log output is safe allowlisted summaries only. Owner STOP (`~/.nexus-host/owner-stop.json` / `host-off`) and one-time approvals preserved. No background persistence or modifications to Windows Task Scheduler.
5. Supervisor should be bounded, with finite deadline. It must not kill any process it did not itself spawn. For active orphan Codex CLI: bounded wait for exit, then recovery; if still running/uncertain, STOP. External operator will kill a test-only process only after exact independent PID+path+creation check.
6. `supervisor.test.mjs` must include at least: healthy completion, real controller SIGKILL while fake Codex still alive then independently allow fake to exit → auto-recover with exact UUID and **effect once**; missing UUID → STOP; active orphan timeout → STOP no replay; owner STOP → STOP; corrupted/foreign state → STOP; altered manifest/CLI hash/wrong branch → STOP; second invocation after completion → no duplicate; maxResume exhausted → STOP; synthetic secret canary absent. Preserve existing 21 tests of controller/pilot.
7. Make test-only mock behavior bounded: currently fake-codex hold loops. Add a test mode `slow-exit` that waits ~1500–2500ms, exits nonzero on its own (no manual killing) while its original parent controller is killed once externally. Or create an equivalent explicit test-only timer. Tests must use fake Node processes in OS tmp and clean up ONLY exact child processes they spawned.
8. README: document manifest, supervisor CLI, recovery rules, security assumptions, exact limits. Distinguish this from NEXUS Host supervisor and Codex GUI auto-resume; no production deployment.
