# NEXUS 0.5.2 — этап 1: архитектура политик

Новый модуль `nexus-host/policy.mjs` (чистые функции, без ввода-вывода) + `policy.test.mjs` (16 тестов).
Интеграции в работающий код на этом этапе нет: 0.5.1-b ведёт себя как прежде.

## Аудит текущих механизмов 0.5.1-b

| Механизм | Где | Проблема для 0.5.2 |
|---|---|---|
| `HARD_DENY` | `capabilities.mjs` | Смешаны 4 разных класса: оболочки (запрет), менеджеры паролей (должно быть «защищено», ур. 2), админ-UI (разрешить с запретом страниц), IDE/explorer (решение владельца — разрешить) |
| `inputApps` / `allowedApp()` | `gui.mjs:130`, `procs.mjs:75` | Ручной allowlist — противоречит N-01 |
| `launchApps` + `manage_app_access` | `apps.mjs` | Запуск только после согласия на каждое приложение — противоречит N-01 |
| Консенсус на закрытие | `consent.mjs` | Одноразовый, TTL 120 с, цель повторяется — хорошая основа N-04, но нет уровней и поля «последствия» |
| Чтение файлов | `files.mjs`, `v3/actions.mjs` | Только границы workspace; нет понятия защищённого ресурса |
| Редакция UIA | `gui.mjs:408` | Скрывает текст документов, но не имена файлов/секреты в остальных ответах |
| Финансовая граница | `browser.mjs` `classifyBrowserRisk` | B-01: не учитывает, что кнопка лишь открывает модальное окно |

## Что вводит `policy.mjs`

- **Классы приложений (N-01):** `deny` → Handoff; `protected` (менеджеры паролей) → ур. 2; `ide`; `admin` (Settings/Control/Task Manager, mmc только «Диспетчер устройств»/«Просмотр событий»); `file_manager` (explorer); остальное — `ordinary`, ур. 1 без allowlist. Неизвестный процесс — `deny`.
- Регрессионный тест: каждая запись старого `HARD_DENY` либо остаётся `deny`, либо явно указана в списке перенесённых решениями владельца. `ApplicationFrameHost` остаётся `deny` (в нём рамка Settings).
- **Страницы безопасности (ур. 3):** Windows Security, Smart App Control, учётные записи/вход, приватность, брандмауэр, BitLocker, «Для разработчиков», восстановление, Windows Update.
- **Защищённые ресурсы (N-02):** каталоги (`.ssh`, `.aws`, `.nexus-host`, Bitwarden, Windows Credentials…), файлы (`.env*`, `.npmrc`, `id_*`, `Login Data`…), расширения (`.pem/.pfx/.kdbx`…), имена (`passw/пароль/token/secret…`, кроме исходного кода) и корни, отмеченные владельцем. Матрица: перейти/открыть окно — ур. 1, но с редакцией захвата; list/read/preview — ур. 2; copy/send/modify/delete — ур. 2, одноразово.
- **Фильтр секретов** `redactSecrets` для ответов инструментов, вывода терминала и журналов.
- **IDE:** клавиши запуска и контексты команд (терминал, Command Palette, `>`, Debug Console, Run Task) → `arbitrary_command`, ур. 3. Fail-closed: Enter/многострочный текст автономны только в положительно опознанном редакторе. Файлы-исполнители (`package.json`, lock-файлы, `.git/hooks`, `.vscode/*.json`, workflows, `*.ps1/cmd/bat/sh`…) — запись NEXUS → ур. 3 с diff. Одобренная команда автономна, только если хэш-снимок файлов-исполнителей не изменился с согласия владельца.
- **Согласия (N-04):** запись = уровень, действие, объект, последствия, цель, срок (ур. 2 — 10 мин, ур. 3 — 120 с). Покрывает ровно одну пару действие+объект; ур. 3 — всегда одноразово.
- **A-02:** Блокнот для тестов не запускается холодным стартом → Handoff/другой редактор; при тёплом старте чужие вкладки редактируются.

## Не проверено (на реальном ПК/приложении)

- Имена UIA терминала и Command Palette VS Code/Cursor (эвристики `IDE_COMMAND_CTX`, `IDE_EDITOR_CTX`).
- Заголовки страниц Settings на языке системы владельца.
- Захват/редакция окна Проводника с защищённой папкой.

## Этап 2 — интеграция

1. `gui.allowedApp` и `procs.isAllowedApp` → `classifyApp`; класс `ide` → `classifyIdeInput`; `admin` → `adminPage`.
2. `open_app` для любого приложения: поиск установленных (Start Menu `.lnk` → цель `.exe`, App Paths), проверка `launchableExe`; `manage_app_access` остаётся только для отзыва/запрета.
3. `files`, `inspect_ui`, `capture_screen`, Live View → `resourceDecision` + `redactSecrets`; согласия через `makeConsent`/`consentCovers` поверх существующего `consent.requestGrant`.
4. Профиль `autonomous` на ПК не меняется до этапа 6.

# Этап 2 — политики подключены к работающему коду

| Где | Что изменилось |
|---|---|
| `gui.mjs` | `allowedApp` удалён. Все цели — через `appGate`: обычные/IDE/admin/explorer — автономно; защищённое приложение — разовое согласие на чтение окна или ввод (фокус — без согласия); страница безопасности — согласие на ввод; IDE — `classifyIdeInput`/`classifyIdeClick`. Согласие повторяет вызов один раз и только для того же окна (`policyOk.hwnd`). |
| Системные утилиты | Найдены реальным поиском на Windows CI (Disk Cleanup, dfrgui…). Класс `system_tool` (cleanmgr, msconfig, rstrui, SystemProperties*…): смотреть — автономно, любой ввод — согласие уровня 3 на каждое действие. |
| `procs.mjs` | Закрытие процесса — по классу приложения; закрытие чужого по-прежнему с согласием; kill — только своё. |
| `apps.mjs` + `discover.mjs` | `open_app {app}` открывает любое установленное приложение из меню «Пуск» (ярлык → `.exe`, аргументы ярлыка игнорируются), без выдачи разрешения. `manage_app_access list` показывает установленные с классом; `revoke` = блокировка владельцем (`blockedApps`), снятие блокировки — с согласием. |
| A-02 (временно) | `NOTEPAD_COLD_START_BLOCKED = true`: если Блокнот не запущен или его состояние неизвестно — `owner_action_required`, ничего не запускается. Снимается на этапе 4 после редакции восстановленных вкладок и проверки на ПК. Блокнот и Калькулятор не открываются через discovery. |
| `server.mjs` | `fileGuard` (N-02): чтение/список/копирование/изменение защищённого → разовое согласие; запись в файл-исполнитель → согласие с diff. `search_files` скрывает защищённые имена. Все результаты инструментов проходят `redactDeep` (изображения не трогаются), счётчик `secretsRedacted`. Запись текста с маркером `«redacted»` обратно в файл запрещена — иначе стёрлись бы настоящие значения. |
| `capabilities.json` | Новые ключи: `appAccess` (`policy` по умолчанию / `allowlist` — откат к поведению 0.5.1), `blockedApps`, `protectedPaths`. Существующий профиль на ПК валиден без правок; после установки 0.5.2 он работает в режиме `policy`. |

**Каталог инструментов не менялся.** Каталог шлюза — байт-в-байт копия каталога Host (тест), а шлюз — развёрнутый Worker. Новые описания (`open_app` для любых приложений, поле `purpose` в согласии) требуют передеплоя шлюза → этап 6, с разрешением владельца. До этого ChatGPT видит старые описания, но поведение работает по тем же схемам.

**Осознанное решение:** при согласии на чтение защищённого файла секреты в нём всё равно редактируются (передача секрета в модель — отдельное согласие по ТЗ). Отдельный режим «передать значение» — этап 3 вместе с Handoff.

# Этап 3 — N-03 Owner Handoff + N-08 Task Continuity

**Ограничение этапа:** каталог инструментов не меняется (шлюз = production, этап 6). Поэтому Handoff работает через существующие инструменты:

| Шаг | Как |
|---|---|
| Запрос | Инструмент возвращает `status: owner_action_required` + `handoffId: "h-…"`, `what/where/check`, `paused`, `next`. Паролей/кодов в чат не просить — это в тексте `next`. |
| Пауза | Пока Handoff активен: ввод (mouse/keyboard/focus/open_app/close/process/browser/run_task/файловые записи/confirm_action) → `owner_handoff_active`; при `pause.capture` — также capture_screen/inspect_ui/window_info/browser_snapshot, а кадры Live View не выдаются (через hold сессии, без ошибок виджета). Чтение статуса доступно. |
| Удержание сессии | `session.hold(key, ttl)`: idle-lease (45 с) не завершает задачу и не закрывает окна NEXUS, пока владелец действует; hold ограничен TTL Handoff (10 мин) и максимумом сессии; Stop/finish_task по-прежнему завершают немедленно. |
| Проверка | `task_status {id:"h-…"}` — long-poll до 20 с (шлюз: таймаут 55 с, task_status read-only → повтор безопасен). Проверка по состоянию Windows: `app_window`/`no_window` по UIA-снимку процесса; сбой снимка = `unknown`, никогда не «готово». |
| Продолжение | `done` → `next` называет сохранённый шаг (например `open_app {"app":"notepad"}`), который **ещё не выполнен** — ChatGPT продолжает с него, не повторяя предыдущие. |
| Отказ | `task_cancel {id:"h-…"}` → `declined`, зависимый шаг пропускается. Истечение TTL → `expired`. |
| Непроверяемое | UAC/вход (защищённый рабочий стол — UIA его не видит) и команды в оболочке: `verify: none` → `unverifiable`, ChatGPT обязан проверить последствия инструментами чтения. |

**Источники Handoff:** холодный старт Блокнота (A-02; проверка — появилось окно Блокнота; продолжение — `open_app notepad`), ввод в окно учётных данных Windows (`no_window`), UAC/вход, оболочки/regedit, запрещённые оснастки mmc. Системные процессы и рантайм NEXUS (svchost, lsass, node, cloudflared…) остаются простым отказом.

**N-08 чекпоинт** `%USERPROFILE%\.nexus-host\tasks\t-<id>.json`: этап (последний рабочий инструмент), выполненные внешние операции с idempotency-ключами, ожидаемое действие владельца, созданные NEXUS окна/вкладки, проверки, ошибки, статус `active/waiting_owner/finished/interrupted`. Без аргументов, введённого текста и содержимого файлов; цели — через `redactSecrets`. Хранится 50 последних файлов. `task_status` без id показывает `ownerAction`, `checkpoint` и `lastInterrupted` (после Stop или перезапуска Host).

**Идемпотентность:** внешние операции = согласованные рискованные действия (платёж/необратимое в браузере, изменение/удаление/копирование защищённого файла, запись в файл-исполнитель, ввод в системную утилиту/страницу безопасности, произвольная команда IDE). Ключ = sha256(what+target). Успешное выполнение записывается в журнал; повторный запрос той же операции в течение 24 ч — в том числе после Stop или перезапуска Host — приходит как согласие с целью «ПОВТОР (уже выполнено …)»: старая цель его не подтверждает, владелец видит, что это повтор. Обычные клики/ввод без согласия не журналируются (иначе блокировались бы законные повторы).

**Не проверено на реальном ПК:** сам цикл Handoff на Windows владельца; поведение окна CredentialUIBroker в UIA-снимке (предположение: виден как обычное окно процесса).
