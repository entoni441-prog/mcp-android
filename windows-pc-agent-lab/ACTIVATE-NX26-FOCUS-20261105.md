## 3. Безопасная процедура после разрешения

1. Повторно установить текущий статус `Online`, health/Gateway, PID и точные команды Host/supervisor, отсутствие `host-off` и owner stop. Сверить прежние SHA-256 двух файлов; при несоответствии **STOP**, не заменять неизвестную базу.
2. Создать **новую датированную резервную копию двух действующих файлов**. Проверить совпадение SHA-256 и размеров 2/2. Сохранить путь в журнал.
3. Подготовить автономный установщик с durable state, preflight `--check`, точными проверками PID перед остановкой, автоматическим откатом. Не использовать `taskkill /t` и не трогать сторонние процессы/окна.
4. Остановить только подтверждённые Host/supervisor, атомарно заменить ровно два файла из закреплённого SHA, проверить SHA-256, запустить через уже существующую `NEXUS-Host-Run`.
5. Дождаться **нового** Host/supervisor, health и Gateway Online. При неудаче — восстановить оба файла из резервной копии, проверить SHA и восстановить Host/supervisor. В журнале зафиксировать явный `installed_verified` или `rollback_verified`.
6. Выполнить адресный **реальный E2E NX-26**: последовательно открыть принадлежащие NEXUS `charmap` и `msinfo32`, перекрыть заголовок и проверить `focus_window` → `titlebar_occluded`, `occlusion.verified=true`, без посторонних кликов. После устранения перекрытия убедиться в штатном восстановлении фокуса. Закрыть только свои тестовые окна.
7. Отрицательные результаты Win32/UIA без подтверждения должны возвращать `titlebar_not_reachable`; `Control Panel/csrss` остаётся за прежними политиками. Не повторять NX-13, NX-19, NX-21 без причины. Сохранить точный результат и чекпоинт.

**STOP:** если изменились PID, происхождение, SHA, проверки CI, Host identity или есть неоднозначность с политиками — без попыток обхода. Текущий установленный Host продолжает работать, пока отдельное разрешение не получено.
