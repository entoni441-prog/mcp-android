# NEXUS — системная клавиатура Samsung во всех текстовых полях, включая пароли

Дата: 2026-11-08. Запрос владельца: системная Samsung клавиатура должна открываться после касания обычных Edit/Document/ComboBox, а также password/PIN/OTP полей, чтобы печатать и стирать без отдельного диалога отправки. На телефоне это **прямое действие владельца**, не ввод текста моделью.

## Подтверждённые факты и границы
- Live v10.1: pinch, панорамирование изображения, реальное перемещение окна Windows и Minimize = подтверждённый Samsung E2E PASS.
- В `experiment/nexus-live-v11-samsung-ime-20261108` реализован автозапуск обычного IME, передачa Unicode, Backspace и Enter. Gateway 89/89 тестов PASS. Password / PIN / OTP пока намеренно исключены и НЕ объявляются поддерживаемыми.
- Host `gui.keyboard_action` отказывает на `before.elem.isPassword===true` или неопределённом типе поля. Обычный `tools/call` проходит через интерфейс ChatGPT, значит **запрещено помещать пароли и секреты в параметры этого инструмента**. Снятие Host-проверки без другого канала недопустимо.
- Пользователь прямо требует вводить собственные пароли непосредственно системной клавиатурой Samsung. Это не разрешение передавать их модели или обходить защиту команд в терминале/операций безопасности.
- Windows secure desktop (UAC/LogonUI/заблокированный компьютер) требует отдельной архитектуры и может быть недоступен при выключенном Host. Не обещать его работу до практического подтверждения.

## Безопасная целевая архитектура
1. Виджет остаётся внутри ChatGPT Live и получает пользовательский ввод через настоящую Android HTML-переменную `<input type=password>` при парольном поле (без сохранения/autofill подсказок и без зеркала текста Windows).
2. Для обычных текстовых полей — уже реализованный поток `keyboard_action`. Для чувствительных — **новый прямой HTTPS endpoint Gateway**, не `tools/call`, не `ui/message`, не `structuredContent`, не chat model.
3. Владелец лично открывает чувствительное поле и подтверждает начало защищённой короткоживущей сессии с NEXUS (owner-auth / привязка к текущему окну и фокусу). Авторизация не должна превращаться в подтверждение каждого символа; нужен ограниченный в сроках grant, одноразовые номера операций и запрет replay.
4. Сервер Host принимает secure-input только от авторизованного Gateway-канала и проверяет совпадение `PID/HWND`, UIA focused control и текущего password/OTP-флага. Данные не возвращаются в инструменты и не попадают в audit/log/metrics, включая текст ошибки, query strings и traces. Результат только `{ok,typedCount}`.
5. Передача через TLS, с временным владельческим grant и ограничением `Origin`, XSS/CSRF, лимитом на текст/скорость и строгим Content Security Policy. Не использовать пароль владельца NEXUS как пароль Windows.
6. Предупреждать и блокировать secret entry при непроверенном фокусе, смене окна, ошибке сети, UAC, shell/IDE терминале, unknown outcome. В этих случаях не повторять ввод автоматически, не формировать секретные записи в рабочем процессе.
7. Обычный ввод сохраняет понятную UX-модель: касание → появление клавиатуры Samsung → ввод/удаление; защищённый ввод сохраняет то же UX после одного короткого owner unlock.
8. Тесты: секрет не встречается в `tools/call`, journal, `audit`, model response, session storage; проверка привязки к exact field, срок, replay, смена фокуса, отказ без авторизации, захват UAC/shell, Backspace/OTP, композитные IME-события и Android real E2E.

## Порядок
- Сначала опубликовать только обычный проверенный Gateway v11 после обязательного owner consent.
- Защищённый режим создать и проверить в отдельной ветке с независимым security review Claude, без изменения production/main. Host/Gateway менять только после отдельной проверки.
- Итоговой приёмкой считать реальный Samsung ввод обычного текста, затем тест с **временным вымышленным тестовым паролем** в безопасном тестовом поле. Никогда не просить пользователя передать реальные пароли в чат.

**Статус:** Требование принято; защищённый прямой канал пока **НЕ РЕАЛИЗОВАН**.
