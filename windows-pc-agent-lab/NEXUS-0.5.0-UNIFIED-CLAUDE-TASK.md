## Последний проверенный контекст (не начинать с нуля)
- На Windows NEXUS Host **0.4.2** активен, 29 MCP-инструментов доступны; `get_status`, `get_capabilities`, `host_diagnostics` подтверждены ChatGPT. `gui_input=false`, `screen_capture=true`, `ui_read=true`, остальные привилегии выключены; `fileError=null`.
- Сквозная проверка мыши/клавиатуры, скриншотов и UIA в Notepad уже выполнена в 0.4.1 (фаза B). В 0.4.2 есть `confirm_action` и `host_diagnostics`, ownership/consent, focus fallback и журналы. Не повторять полностью старые этапы.
- На Host логи cloudflared фиксировали `datagram manager error: timeout: no recent network activity` с быстрым автоматическим переподключением; использовать эту улику при решении устойчивости канала вместо догадок.
- В GitHub есть `experiment/nexus-0.4.3-ownership-20261101` с двумя коммитами исправлений поверх 0.4.2; **данная 0.5.0 ветка создана от этой экспериментальной ветки, чтобы не потерять изменения**. Не предполагать, что 0.4.3 была установлена на ПК.
- Источники: `windows-pc-agent-lab/NEXUS-0.4.2-REPORT.md`, `windows-pc-agent-lab/nexus-host/LIVE-VIEW-DESIGN.md`, код текущей ветки. Сначала прочитать и использовать, не реконструировать код по памяти.

## 1. Live View прямо внутри ChatGPT — обязательная часть 0.5.0
Пользователь хочет видеть Windows, курсор, открытие окон и действия агента **в том же чате**, на Android и ПК, аналогично TinyFish LIVE. Должно работать во время продолжающейся беседы, а не только как одиночный скриншот.

**Основная реализация A — MCP App UI:** ресурс/виджет `watch_nexus` или `nexus_live_view` с поддержкой inline/PiP/fullscreen по возможностям хоста; отдельные data-tools и render-tool, не перерисовывать iframe на каждом обычном вызове инструмента. Следовать текущим официальным инструкциям:
- https://developers.openai.com/plugins/build/chatgpt-ui
- https://developers.openai.com/plugins/concepts/ui-guidelines
- https://developers.openai.com/plugins/reference
- https://developers.openai.com/plugins/build/app-quickstart
**Не утверждать поддержку конкретного клиента до настоящей проверки.** Для Android PiP может быть представлен как fullscreen. Разработать интерфейс, безопасный для обоих представлений.

**Одновременно реализовать вариант B — внешнюю защищённую страницу /live**, доступную с телефона и ПК по ссылке из чата, если UI-ресурс не рендерится конкретным клиентом. Это полноценная часть *того же релиза*, не отдельная версия: работоспособная трансляция должна быть даже при ограничении ChatGPT UI.

Технический минимум:
- Поток обновляющихся кадров (MVP 2 кадра/с, регулируемая частота ~0.5–4), видимый курсор, согласованные координаты и понятное состояние «LIVE / пауза / офлайн».
- Наблюдение по инициативе владельца; кнопки Start/Pause/STOP, отдельная capability `live_view` по умолчанию false, индикатор на Host/Windows во время захвата. По STOP прекращать захват на источнике; без зрителя поток не генерировать.
- Использовать существующие NEXUS Host/Gateway/Cloudflare. Ни новой платной подписки, ни дополнительных постоянно работающих платных сервисов.
- Защищённая передача HTTPS/WSS или опрос HTTPS, короткие приватные авторизованные сессии; строго проверять пользователя **на шлюзе и у Host**, не раскрывать NEXUS_TOKEN клиенту, не использовать открытый публичный URL для кадров. CSP (connectDomains/resourceDomains/frameDomains) только разрешённых источников, корректно обрабатывать мобильные ограничения cookies/iframe; секреты не класть в URL/логи/JavaScript.
- Никакой записи кадров/текста экрана по умолчанию, `Cache-Control: no-store`, защита от неавторизованного просмотра, brute-force и повторного применения токенов. Экран может содержать пароли: явная индикация и экстренный STOP обязательны.
- Виджет не даёт дополнительных полномочий управления ПК; наблюдение и ввод — **разные** capabilities.

## 2. Полезное управление Windows, а не только Блокнотом
- Убрать искусственное узкое ограничение `Notepad, CalculatorApp` как окончательную функциональность. Реализовать безопасное **расширение списка приложений владельцем** через существующую модель согласия/разрешений (включая запуск и фокус разрешённого приложения), без ручного редактирования JSON на каждый новый запуск.
- Сохранить защиту от случайного ввода в чужое окно: UIA/HWND проверка реально активного окна, HARD_DENY системных/секретных интерфейсов, защита от ввода в неверный процесс; логировать ошибки, не подменять фокус принудительным вводом.
- Не обходить политику согласия через клики, клавиатуру, оконные меню, горячие клавиши и закрытие процесса. Любое закрытие пользовательской/неизвестной вкладки или окна — **точечное consent_required → confirm_action**, после подтверждения возможно. Свои безопасные тестовые вкладки закрывать автономно. Несохранённые изменения требуют выбора владельца.
- Обеспечить независимую чистую тестовую вкладку в Windows 11 Notepad (вместо работы на открытом владельцем документе). UIA возвращает `createdByNexus` и ownership/selected tab; незнакомая вкладка никогда не считается своей по одному PID.
- Доработать `focus_window` с обратной связью о методах и фактическом HWND; если нельзя — честный отказ, без случайного клика.
- Базовые сценарии управления: открыть/переключить/прочитать UI/ввести/кликнуть/прокрутить/закрыть по согласию, безопасная обработка диалогов, восстановление интерфейса после задачи. Не добавлять произвольный shell/командный запуск как способ расширить GUI.

## 3. Полноценное управление браузером через NEXUS
- Довести существующие `browser_open`, `browser_snapshot`, `browser_action` до пригодного end-to-end сценария; не создавать ещё одну параллельную браузерную подсистему.
- По умолчанию безопасный независимый профиль, но предусмотреть **отдельно одобренный владельцем** сценарий работы с уже авторизованным браузерным профилем, без передачи/чтения cookies, паролей и токенов. Если технически небезопасно — явно документировать границу, а не обходить её.
- Поддержать навигацию, ввод, клики, ожидание загрузки, вкладки, состояние страницы, ошибки и восстановление после кратких тайм-аутов. Подтверждение владельца перед необратимыми, финансовыми и внешне отправляемыми действиями. Не открывать приватные адреса/localhost произвольно.
- Не менять текущий `browser=false` без команды владельца.

## 4. Устойчивость и понятная диагностика
- Довести диагностику `pc_offline` vs `pc_timeout` vs разрыв cloudflared/QUIC. Определять состояние Host, Gateway, registration/KV, живость туннеля, недавний reconnect; выдавать конкретную причину и безопасное восстановление.
- Повторять автоматически только чтение; действия со сторонними эффектами не повторять без проверки результата/idempotency.
- Проверить адекватное поведение при завершении сессии Claude Code, обновлении туннеля, устаревшем URL и перезапуске Host. Не включать автозапуск Windows без согласия владельца.
- Журнал без введённых текстов, токенов и кадров; метки времени, трассировка операции и корреляция ошибок.

## 5. Один пакет и одна установка (НЕ делать мелкие фазы)
- Все перечисленные **функциональные модули** (включая Live View) довести до code-complete в **этой экспериментальной ветке**, с техническим отчётом о реальных ограничениях UI ChatGPT.
- Существующую архитектуру и проверенные модули использовать повторно; не пересоздавать проект, авторизацию, туннель, проектную папку, весь Gateway или ранее завершённые тесты.
- Автоматические CI unit/integration/safety проверки обязательны для OAuth, доступа к кадрам, согласия на закрытие, UX-виджета, мыши/клавиатуры, Gateway/Host и безопасного rollback. После сборки пакета — **один комплексный прогон**. Не требовать десятков промежуточных живых приёмок и ручного прохождения одинаковых сценариев.
- Не расширять полномочия silent-default, не записывать секреты, не трогать рабочий Host 0.4.2, main, чужие production Workers и другие проекты во время разработки.
- Перед финальной установкой подготовить список файлов, manifest SHA-256, резервную копию работающей версии, точный одноразовый `ACTIVATE-0.5.0.md` (Host smoke → Gateway deploy только после PASS → проверка через настоящий коннектор → rollback). Ни установки, ни Gateway deploy без отдельной команды владельца.
- После установки: **ChatGPT Plugins → NEXUS — Windows PC → Refresh tools → новый чат**, проверить каталог/версию, затем один реальный интеграционный сценарий на ПК с владельцем: управление документом, согласие на чужую вкладку, браузер, Live View в Android/PC, STOP, диагностика. Найденные реальные дефекты фиксировать и исправлять адресно.

## Критерий завершения
Владелец может из ChatGPT **видеть** свою Windows в живом окне на телефоне/ПК и **управлять** разрешёнными приложениями/браузером через агента с точечным согласием на рискованные действия. Один пакет, одна активация, единая живая приёмка, затем только необходимые исправления. Если встроенный виджет технически ограничен клиентом ChatGPT — должен работать реализованный внешний Live View, с документированной причиной ограничения; не откладывать весь Live View на ещё один релиз.

## Формат ответа Claude
Прямо указать: что готово, что ещё блокировано (факт/причина), число инструментов, commit SHA, CI Windows/Linux/Gateway, результаты защиты, встроенный ChatGPT виджет (что проверено на реальном клиенте, что нет), внешний Live View, перечень поставки, rollback, один нужный шаг от владельца. Не заявлять, что поставка уже сделана, пока нет проверки на ПК.
