## Запрос владельца
Экран NEXUS Live в ChatGPT на Samsung слишком маленький. Нужно прямо в чате раздвигать два пальца для приближения мелких кнопок Windows (включая «Свернуть»), перемещать увеличенный экран, а затем точно нажимать нужный элемент; не открывая браузер и не подменяя удалённое управление экранной лупой Windows.

## Реализовано
1. В `nexus-gateway/src/widget.mjs` жест двумя пальцами изменяет визуальный масштаб Live от **1× до 5×** относительно центра между пальцами.
2. После увеличения одним пальцем можно перемещать увеличенное изображение; панорамирование ограничено границами экрана. Кнопка `1.0× ↺` (при увеличении отражает текущий коэффициент) возвращает исходный масштаб.
3. Двухпальцевые жесты, перетаскивание и отменённые указатели **не посылают mouse_action/keyboard_action**. Только отдельный короткий тап после завершения жеста может инициировать обычный клик при включённом Owner Touch и актуальном кадре. Одинарный/двойной тап и STOP остаются под Host-политикой.
4. При увеличении Live запрашивает кадры до **1600 px** по ширине вместо 960 px (если Host может их предоставить), не меняя разрешение Windows и privacy-маскирование.
5. Переход к координатам Windows рассчитывается по `img.getBoundingClientRect()` **после CSS-transform**, а не по контейнеру, чтобы попадание на увеличенное изображение соответствовало исходной точке рабочего стола.
6. В `widget-input.mjs` добавлены чистые функции `anchoredZoomPan` и `clampZoomPan`.
7. Новый MCP Apps URI `ui://nexus/live-view-v9.html` предотвращает прежнюю проблему кеширования v8. В Gateway оставлен устаревший URI v8 для совместимости; Host/Gateway `catalog.mjs` остаются побайтово равными (Host не обновляется).
8. Версия внутреннего appInfo `9.0.0-pinch-zoom`.

## Не считать PASS
- Реальная работа жестов внутри мобильного приложения ChatGPT на Samsung **ещё не проверена**. Browser iframe / touch event routing может отличаться от симуляции. Не обещать успешный мобильный E2E до демонстрации владельцем.
- Нажатие именно на кнопку Minimize окна NEXUS Host / WindowsTerminal по-прежнему отдельный **FAIL direct-touch**, описанный в общем handoff разделе 12. Увеличение помогает попаданию пальцем, но не исправляет ошибку Host `shell_command → owner_handoff_active`.
- Запрос на `live_control resume` для зависшего handoff не выполнять без нового явного указания владельца. Host security policy не ослаблена.
- Предыдущие URI v7/v8 в ресурсах по-прежнему могут отдавать текущий HTML; это не настоящий code rollback. При rollback использовать предыдущий Cloudflare Worker deployment.
