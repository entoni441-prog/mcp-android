# NEXUS NX-13 — фактическая цепочка Windows UIA Edge Translate

**Дата:** 05.11.2026. **Режим:** только чтение UIA и фиксация доказательств; установленный Host 0.6.1d, Gateway, main, политики и runtime-код не менялись.

## Источник

- ПК владельца, текущий Edge в отдельном профиле NEXUS, французская статья `https://fr.wikipedia.org/wiki/Wikip%C3%A9dia`.
- PID основного окна Edge в этом наблюдении: `18972`, HWND окна: `461222`.
- Данные сняты **непосредственно из UI Automation**: `AutomationElement.FromHandle(MainWindowHandle)`, поиск `NameProperty='Закрыть'` по `TreeScope.Descendants`, подъём через `TreeWalker.ControlViewWalker.GetParent()`.
- Для каждого уровня записаны `ControlType`, `ClassName`, `AutomationId`, `Name`, `NativeWindowHandle` (HWND), `ProcessId`. Цепочка остановлена на основном Edge HWND. Значения PID/HWND **только для этой сессии** и никогда не должны быть константами теста.
- Нажатий на кнопки не выполнялось. Снята не догадка о структуре, а цепочки **двух разных** кнопок «Закрыть» одного Edge.

## A. Положительный образец: кнопка закрытия Edge Translate

| Глубина от кнопки | ControlType | ClassName | AutomationId | Name | HWND | PID |
|---:|---|---|---|---|---:|---:|
| 0 | Button | `ImageButton` | пусто | `Закрыть` | 0 | 18972 |
| 1 | Pane | `BubbleFrameView` | пусто | пусто | 0 | 18972 |
| 2 | Pane | `NonClientView` | пусто | пусто | 0 | 18972 |
| 3 | Text | `RootView` | пусто | `Перевести страницу с французский?` | 0 | 18972 |
| 4 | Pane | `Chrome_WidgetWin_1` | пусто | `Перевести страницу с французский?` | **199162** | 18972 |
| 5 | Pane | `BrowserRootView` | пусто | `Wikipedia - Wikipedia: Microsoft Edge` | 0 | 18972 |
| 6 | Window | `Chrome_WidgetWin_1` | пусто | окно Wikipedia, Microsoft Edge | **461222** | 18972 |

Ключевое: на глубине 1 **не** `Chrome_WidgetWin_1`, а `BubbleFrameView` без HWND. Отдельный HWND панели перевода есть только на глубине 4; HWND панели **отличается** от HWND главного окна, но цепочка UIA доходит до главного окна того же Edge PID. Это объясняет, почему текущее правило `consent.mjs:70–77` не срабатывает.

У кнопки закрытия *всего* Edge нет именованной панели перевода, нет промежуточного отдельного popup HWND. Это действие **обязано оставаться** под `consent_required`.

## Требования к дальнейшему исправлению (без патча на этом этапе)

1. Разрешать локальное закрытие только кнопки `Button/ImageButton` с `Name=Закрыть/Close` **после** ограниченного подъёма к строго распознанному native popup с названием перевода (например, максимум 6–8 переходов).
2. Требовать popup `Chrome_WidgetWin_1` с **ненулевым и отличным от главного** HWND, совпадение PID с Edge и подтверждённую цепочку предков до основного окна Edge, на котором инициировано действие. **Не путать отдельный HWND поповера и HWND окна.**
3. При отсутствии любого признака, неоднозначности, другом языке или структуре, неизвестном окне и особенно для `EdgeWindowsCaptionButton/view_7` возвращать прежнее `consent_required` (fail-closed).
4. В тестах воспроизвести обе снятые цепочки, а также старую плоскую структуру из существующего теста и негативные случаи: без имени popup, без HWND, равный главному HWND, чужой PID, превышенная глубина, название без сигнатуры перевода.
5. Не менять установленный `nexus-host`, Gateway, `main` или политики без отдельного разрешения. Сначала отдельный патч в экспериментальной ветке, адресные тесты, CI и независимое ревью.

## Прежний воспроизведённый FAIL

По [протоколу реальной приёмки](./NEXUS-NEXT-0.6.1d-REAL-ACCEPTANCE-20261105.md), когда панель перевода была открыта, попытка `mouse_action({action:'click',x:783,y:109})` вызвала `consent_required` для **основного** окна Edge, а не dismiss панели. Согласие отменено, окно не закрыто. Нынешняя диагностика установила точную иерархию, необходимую для теста. Координаты экранных снимков/PowerShell могут различаться из-за DPI и не являются устойчивыми идентификаторами.
