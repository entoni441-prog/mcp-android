# NEXUS — защищённый дистанционный вход Windows из ChatGPT Live
Дата постановки: 2026-11-07. Статус: ТРЕБОВАНИЕ / НЕ РЕАЛИЗОВАНО. Только экспериментальная ветка; production и настройки безопасности не менять.

## Точное требование владельца
После перезагрузки Windows, даже до входа в профиль пользователя, в ЧАТЕ ChatGPT должна появляться трансляция/состояние экрана входа (Live) и защищённое **окно ввода** для личной авторизации владельца с Samsung Android. Цель — полностью удалённо входить в Windows, не подходя к физическому ПК. Поле ввода должно отображаться в интерфейсе чата, если хост-платформа действительно поддерживает отдельную доверенную поверхность авторизации.

## Принцип безопасности
- Нельзя просить вводить PIN/пароль Windows в обычное сообщение ChatGPT, MCP-аргументы или пользовательский запрос, передавать его языковой модели, журналу, Cloudflare Worker или GitHub.
- Учётные данные должны приниматься исключительно доверенным owner-only компонентом авторизации (с независимой аутентификацией, защищённым каналом и без доступа модели к содержимому).
- Не обходить Winlogon/UAC/secure desktop, не включать автологин, не ослаблять безопасность Windows, не открывать публичный RDP-порт.
- Текущий NEXUS Host и Live запущены в пользовательской сессии и НЕ доказывают возможности захвата/ввода на защищённом экране входа. Встроенное секретное поле прямо в ChatGPT не считать доступным, пока экспериментально не подтверждены API и границы безопасности клиента.

## План инженерной реализации
1. Инвентаризировать установленную редакцию Windows, уже доступные средства удалённого управления и их способность работать до интерактивного входа после cold boot/reboot.
2. Найти поддерживаемый Windows механизм удалённого входа до логина, предпочтительно с использованием существующей безопасной инфраструктуры. Оценить RDP по частной сети, если позволяет редакция Windows, либо имеющееся unattended remote desktop приложение. Никаких покупок и дублирования платных сервисов.
3. Реализовать независимый pre-logon статусный канал BOOTING → LOGIN_REQUIRED → OWNER_AUTHENTICATING → DESKTOP_READY → NEXUS_ONLINE.
4. Проверить возможность отдельной доверенной поверхности авторизации внутри ChatGPT UI без раскрытия секретов модели. Если она недоступна, предоставить безопасный переход в проверенный Android-клиент/отдельную защищённую страницу, возвращая в чат только статус; прямо объяснить это ограничение владельцу.
5. Провести end-to-end тест: перезагрузка → появление Live/status до входа → личная дистанционная авторизация с телефона → запуск пользовательской сессии → автоматическое восстановление NEXUS → подтверждённая трансляция рабочего стола. Проверить STOP, отзыв доступа, обрыв связи, чужой клиент, аудит без секретов и восстановление после ошибки.
6. Только после подтверждённого независимого канала входа и отдельного разрешения владельца выставлять logonChannelVerified=true, иначе существующий запрет на перезагрузку сохранять.

## Текущий чекпоинт
Экспериментальная ветка experiment/nexus-lock-login-recovery-20261107, чекпоинт 10082f495850db2405a585e754a4d67eb80928fd: Windows Lock подтверждён, NEXUS остаётся online, но возможность дистанционной авторизации после reboot НЕ подтверждена; logonChannelVerified=false. Замечена отдельная ошибка: lock с dryRun:true фактически блокирует Windows — исправлять отдельно, не путать с дистанционным входом.

## Критерий принятия
Владелец с телефона самостоятельно входит в Windows после реальной перезагрузки; пароль/PIN не попадает в модель и её логи; соединение NEXUS восстанавливается; main/production и политики безопасности сохраняются до отдельного одобрения установки.
